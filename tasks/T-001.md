## 1. Описание (оператор)

Подготовить репозиторий к разработке: каталоги из архитектурного документа (пустые с `.gitkeep`, где нужно), общие конфиги и pre-commit, чтобы все следующие задачи начинались в одинаковых условиях. Код приложения не пишем — это T-002 и T-004.

## 2. Критерии приёмки

- **AC-1.** Структура каталогов соответствует docs/03-architecture.md §3 (`backend/`, `frontend/`, `deploy/`, `.github/workflows/`, `tasks/`).
- **AC-2.** `.editorconfig` (UTF-8, LF, отступы: 4 для Python, 2 для остального), `.gitignore` (Python, Node, `.env`, артефакты сборки, покрытия, IDE), `.gitattributes` (LF).
- **AC-3.** `pre-commit` настроен: trailing whitespace, end-of-file, check-yaml/json, check-merge-conflict, detect-private-key, запуск `validate_catalog.py` при изменении `docs/catalog/*.csv`. Хуки ruff/prettier/eslint добавляются, но активируются, когда появятся backend/frontend (или настроены так, чтобы не падать на пустых каталогах).
- **AC-4.** `pre-commit run --all-files` проходит на текущем репозитории.
- **AC-5.** В CLAUDE.md, раздел «Команды», добавлена команда установки и запуска pre-commit.

## 3. Предложение (агент, `/task-start`)

### 3.1 Понимание задачи

Подготовить «пустой, но правильный» монорепо: каталоги верхнего уровня из architecture §3, общие правила форматирования файлов (`.editorconfig`, `.gitattributes`, `.gitignore`) и pre-commit, который уже сейчас проверяет общие вещи (пробелы, концы строк, YAML/JSON, конфликты, приватные ключи, справочник), а хуки ruff/prettier/eslint заранее прописаны и сами «оживут», когда появятся `backend/` (T-002) и `frontend/` (T-004). Кода приложения нет. Цель — чтобы следующие задачи начинались в одинаковых условиях на любой машине (в т.ч. на Windows оператора).

### 3.2 Подход

1. **Каталоги:** `backend/`, `frontend/`, `deploy/`, `.github/workflows/` — каждый с `.gitkeep`; `tasks/` уже есть. Внутреннюю структуру (`app/core`, `src/features` …) не создаю — её задают T-002/T-004 (см. вопрос 3).
2. **`.gitattributes`:** `* text=auto eol=lf` + явные `binary` для картинок/шрифтов (`png, jpg, ico, webp, woff2`). Важно: у оператора `core.autocrlf=true` — без этого файла git начнёт превращать LF в CRLF при checkout.
3. **`.editorconfig`:** `root`, UTF-8, LF, `insert_final_newline`, `trim_trailing_whitespace`; 2 пробела по умолчанию, 4 — `*.py`; `Makefile` — tab; `*.md` — без обрезки хвостовых пробелов (двойной пробел = перенос строки).
4. **`.gitignore`:** переписать компактно под проект вместо полного шаблона GitHub для Python. Причина: в шаблоне есть `lib/` и `lib64/` — они молча проигнорируют будущий `frontend/src/lib/`. Разделы: Python (`__pycache__`, `.venv`, `.mypy_cache`, `.ruff_cache`, `.pytest_cache`, `.hypothesis`, `*.egg-info`), Node (`node_modules`, `.pnpm-store`, `*.tsbuildinfo`), сборка (`dist/`, `build/`, `dev-dist/`), покрытие и отчёты (`.coverage*`, `htmlcov/`, `coverage/`, `coverage.xml`, `playwright-report/`, `test-results/`), секреты (`.env`, `.env.*`, но `!.env.example` — он нужен в T-007), IDE/OS (`.idea/`, `.vscode/*` кроме `extensions.json`, `.DS_Store`, `Thumbs.db`), локальные настройки Claude (`.claude/settings.local.json`). Lock-файлы (`uv.lock`, `pnpm-lock.yaml`) **не** игнорируются.
5. **`.pre-commit-config.yaml`:**
   - `pre-commit/pre-commit-hooks` (версия закрепляется на момент реализации): `trailing-whitespace` (`--markdown-linebreak-ext=md`), `end-of-file-fixer`, `mixed-line-ending --fix=lf`, `check-yaml`, `check-json`, `check-merge-conflict`, `detect-private-key`, `check-added-large-files` (`--maxkb=500`; справочник сейчас 34 КБ).
   - `local`-хук `validate-catalog`: `language: python`, `entry: python docs/catalog/validate_catalog.py`, `files: ^docs/catalog/.*\.csv$`, `pass_filenames: false`. `language: python` вместо `system` — потому что на Windows `python3` указывает на заглушку Microsoft Store (проверено: «Python was not found»), а в окружении pre-commit `python` есть всегда.
   - `local`-хуки **ruff** (`ruff check --fix`, `ruff format`) с `files: ^backend/.*\.py$`, запуск через `uv run --project backend …`; **eslint** и **prettier** с `files: ^frontend/`, запуск через `pnpm --dir frontend …`. Пока файлов нет, pre-commit их пропускает («(no files to check) Skipped»). Версии инструментов будут браться из `uv.lock` / `pnpm-lock.yaml` — одна версия и в pre-commit, и в CI, и в редакторе (альтернатива — зеркала `ruff-pre-commit`/`mirrors-prettier` — даёт вторую версию, а `mirrors-prettier` заархивирован).
6. **Существующие файлы:** хуки поправят мелочи (например, хвостовые пробелы в мокапе `docs/07-ui-ux.md:63`) — отдельным коммитом `style:`, чтобы его было легко просмотреть.
7. **Команды:** в CLAUDE.md «Команды» — установка и запуск pre-commit; в README — короткий раздел «Первичная настройка» (в BACKLOG у задачи указано «README команд», в AC-5 — CLAUDE.md; см. вопрос 4).

Уроки: **L-003** (pre-commit — новый инструмент, способ установки согласую — вопрос 1), **L-001/L-002**.

### 3.4 План тестов

Кода нет, поэтому «тесты» — воспроизводимые проверки командами; каждая запускается сначала до изменения (RED), потом после (GREEN). Команды и вывод запишу в журнал.

| AC | Проверка | Уровень | Ожидание RED → GREEN |
|---|---|---|---|
| AC-1 | `git ls-files backend frontend deploy .github/workflows tasks` | repo-check | пусто → все пять каталогов присутствуют |
| AC-2 | `git check-attr eol -- README.md docs/catalog/products.csv` | repo-check | `unspecified` → `lf` |
| AC-2 | `git check-ignore -v` на `.env`, `backend/.venv/x`, `frontend/node_modules/x`, `htmlcov/x`, `.idea/x`; и **не** игнорируются `.env.example`, `frontend/src/lib/x.ts`, `uv.lock` | repo-check | `frontend/src/lib/x.ts` сейчас игнорируется (ловушка `lib/`) → не игнорируется |
| AC-2 | `.editorconfig`: наличие секций `[*]`, `[*.py]`, `[*.md]` (проверка глазами, автоматической проверки без новой зависимости нет) | review | — |
| AC-3 | временный файл с хвостовым пробелом → `pre-commit run --files` | negative | хук `trailing-whitespace` падает и исправляет |
| AC-3 | временный файл с `-----BEGIN RSA PRIVATE KEY-----` | negative | `detect-private-key` падает |
| AC-3 | временно сломать порог в копии `products.csv` (порядок порогов) | negative | `validate-catalog` падает; после отката — проходит |
| AC-3 | битый YAML/JSON, маркер `<<<<<<<` | negative | `check-yaml`/`check-json`/`check-merge-conflict` падают |
| AC-3 | `pre-commit run --all-files -v` | positive | ruff/eslint/prettier — `Skipped (no files to check)` |
| AC-4 | `pre-commit run --all-files` | positive | нет конфига → `Passed` по всем хукам (после коммита `style:` с автоисправлениями) |
| AC-5 | выполнить по шагам команды из CLAUDE.md «Команды» в чистом клоне (`git clone . <scratch>`) | smoke | команды работают как написано |

Временные файлы для негативных проверок — в scratch-клоне репозитория, не в рабочей копии.

### 3.5 Изменения контрактов

- API, схема БД, доменные правила, ADR — **нет**.
- Зависимости: новый dev-инструмент **pre-commit** (сам по себе — предмет задачи) и remote-репозиторий хуков `pre-commit/pre-commit-hooks`. На машине оператора сейчас нет ни `pre-commit`, ни `uv`, ни `node/pnpm` — способ установки см. вопрос 1.

### 3.6 Риски, альтернативы, вне рамок

- **Хуки ruff/eslint/prettier в T-001 реально не проверить** — нечего проверять. Риск: на T-002/T-004 окажется, что `entry` нужно поправить (например, eslint по путям от корня). Митигация: в T-002 и T-004 добавить в критерии «pre-commit-хук линтера срабатывает на изменённом файле». Предложу это в «Отложено».
- **`pre-commit run --all-files` проверяет только файлы под git.** Сейчас вся документация untracked — без её коммита AC-4 проходил бы формально (см. вопрос 2).
- **Windows:** `python3` не работает (заглушка Store) — команда `python3 docs/catalog/validate_catalog.py` из CLAUDE.md у оператора не запустится. В рамках задачи — только хук через `language: python`; правку команд в CLAUDE.md и урок предложу отдельно (вопрос 5).
- Альтернатива pre-commit — lefthook/husky: отвергнуто, NFR-MNT-02 и BACKLOG прямо называют pre-commit, и он не требует Node.
- **Вне рамок:** CI (T-006, но pre-commit там будет переиспользован: `pre-commit run --all-files`), `pyproject.toml`/`package.json` и конфиги ruff/eslint/prettier (T-002/T-004), `deploy/*.yml` (T-003/T-007), внутренние подкаталоги `backend/app/*`, `frontend/src/*`, prettier для `docs/` (переформатирует всю документацию — см. вопрос 3).
