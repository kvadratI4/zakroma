## 1. Описание (оператор)

Из BACKLOG: Postgres в `docker-compose.dev.yml`, SQLAlchemy async-сессия, Alembic, тестовая инфраструктура (testcontainers, фабрики, фикстура `clock`).

## 2. Критерии приёмки

Из BACKLOG (follow-up T-002):

- **AC-1.** `GET /api/v1/health` → `200 {"status": "ok", "db": "ok"}`; при недоступной БД — `503` problem+json с `code: db_unavailable`.

Предложены агентом по строке BACKLOG и NFR-REL-03, приняты оператором 2026-10-23:

- **AC-2.** `docker compose -f deploy/docker-compose.dev.yml up -d` поднимает Postgres (порт только на `127.0.0.1`, том для данных, healthcheck); backend подключается к нему после одного шага настройки (`init_dev_env`, см. AC-10). *(уточнено после ответов: было «без настройки»)*
- **AC-3.** `DATABASE_URL` читается из окружения (`postgresql+asyncpg://…`), значения по умолчанию нет: без него — ошибка при старте. *(уточнено после ответов: было «dev-значение по умолчанию, запрещённое в prod»)*
- **AC-4.** Сессия БД — зависимость FastAPI `get_session` (одна `AsyncSession` на запрос, без автокоммита; транзакцию открывает сервис). Пул создаётся в `create_app`, закрывается при остановке приложения.
- **AC-5.** Alembic: async `env.py`, URL берётся из `Settings` (не из `alembic.ini`), имена файлов ревизий `YYYYMMDD_HHMM_<what>`, общая `MetaData` с соглашением имён ограничений. Первая (базовая) миграция — расширение `pg_trgm` и функции `zk_search_norm`, `zk_search_fold` из `schema.sql` (объём — вопрос 2).
- **AC-6.** Тест миграций (NFR-REL-03, часть «пустая БД»): `upgrade head` на пустой БД проходит; `alembic check` не находит расхождений моделей и миграций; функции работают (`zk_search_fold('Малако') = 'малака'`).
- **AC-7.** Интеграционные тесты идут на реальном Postgres в testcontainers (один контейнер на прогон), каждый тест изолирован (стратегия — вопрос 4); данные одного теста не видны в другом.
- **AC-8.** Фикстура `clock` = `FixedClock(2026-11-10 12:00 Europe/Moscow)`; приложение в тестах создаётся с ней.
- **AC-9.** ruff, mypy strict, pytest с покрытием ≥ 80 % — зелёные; `docs/db/schema.sql` и `CLAUDE.md` обновлены (как — вопрос 3).

Добавлены по ответам оператора 2026-10-23:

- **AC-10. Безопасность БД.**
  - Доступа к БД извне нет: в dev порт опубликован только на `127.0.0.1` (подключение по сетевому адресу машины отклоняется); контейнер testcontainers тоже слушает только `127.0.0.1`.
  - Пароль не хранится в репозитории и не передаётся: dev-пароль случайный, генерируется локально в `deploy/.env.dev` (файл в `.gitignore`, агенту запрещено его читать); в compose и коде паролей нет; у тестового контейнера — свой случайный пароль на каждый прогон.
  - Пароль и DSN не попадают в логи, ответы API, `repr` настроек и сообщения об ошибках (`DATABASE_URL` — `SecretStr`).
  - Ничего не уходит в публичные каналы: секреты не могут попасть в коммит (проверка секретов в pre-commit — вопрос 7); БД и тесты не делают внешних вызовов, кроме загрузки образа Postgres с Docker Hub.
- **AC-11.** Стратегия изоляции тестов БД записана в ADR-0011, `docs/08-testing.md` §5 и `.claude/rules/tests.md` (ответ на вопрос 4).
- **AC-12.** Проектная схема не теряется: `docs/db/schema_design.sql` побайтно совпадает с прежним `schema.sql` (`git mv`, 100 % совпадения), `schema_smoke_test.sql` по-прежнему проходит на проектной схеме, во всех ссылках указан новый путь (ответ на вопрос 3).

## 3. Предложение (агент, `/task-start`)

### 3.1. Понимание задачи

Подключить к каркасу T-002 настоящую базу: Postgres для разработки в Docker Compose, асинхронную сессию SQLAlchemy как зависимость FastAPI, Alembic с первой миграцией и тестовую инфраструктуру, на которой следующие задачи (T-010 пользователи, T-011 дома, T-020 справочник) будут писать интеграционные тесты против реального Postgres. Бизнес-таблиц здесь нет — их создают задачи, которые вводят соответствующие модели. Health начинает честно проверять БД.

### 3.2. Подход

1. **`deploy/docker-compose.dev.yml`** — один сервис `db`: образ `postgres:18`, `127.0.0.1:5432:5432`, том `zakroma-pgdata`, `healthcheck: pg_isready`, `env_file: .env.dev` (обязательный). Паролей в файле нет. `deploy/.gitkeep` удаляется. *(изменено: было «пароль `zakroma` прямо в compose»)*
2. **Настройки:** `DATABASE_URL: SecretStr` без значения по умолчанию, валидатор схемы `postgresql+asyncpg://`. Источники: переменные окружения, затем `deploy/.env.dev`, если файл есть (в Docker-образе T-007 его не будет). `extra="ignore"`, чтобы `POSTGRES_PASSWORD` из того же файла не мешал. Unit-тесты настроек читают только окружение (`_env_file=None`). *(изменено)*
3. **`app/db/`:**
   - `base.py` — `DeclarativeBase` с `MetaData(naming_convention=…)`, повторяющим имена Postgres по умолчанию (`%(table_name)s_pkey`, `…_%(column_0_N_name)s_key`, `…_fkey`, `…_idx`; `CHECK` — всегда с явным именем, как в `schema.sql`). Тогда DDL из `schema.sql` и модели дают одинаковые имена, и `alembic check` не видит ложных расхождений.
   - `session.py` — `create_engine(settings)` (`pool_pre_ping=True`, таймаут подключения 3 с), `async_sessionmaker(expire_on_commit=False)`.
   - `app/api/deps.py` — `get_session` (yield `AsyncSession` из `app.state.sessionmaker`), тип `SessionDep = Annotated[AsyncSession, Depends(get_session)]`.
   - `create_app` создаёт engine (подключение ленивое — без БД приложение стартует), `lifespan` вызывает `engine.dispose()`.
4. **Health:** `SELECT 1` через `get_session` с таймаутом; ошибка подключения/таймаут → `AppError("db_unavailable", status=503, title="База данных недоступна")`, в лог — `warning` без DSN. Ответ `{"status": "ok", "db": "ok"}`.
5. **Alembic** (`backend/alembic.ini`, `backend/alembic/env.py`, `script.py.mako`): async-шаблон, `target_metadata = Base.metadata`, `compare_type=True`; URL — из `Settings()`, переопределяется `-x db_url=…` / атрибутом конфига (так тесты гоняют миграции в контейнере). `file_template = %%(year)d%%(month).2d%%(day).2d_%%(hour).2d%%(minute).2d_%%(slug)s`. Первая ревизия `…_baseline_search_functions`: `CREATE EXTENSION IF NOT EXISTS pg_trgm`, обе функции дословно из `schema.sql`; `downgrade` — `NotImplementedError` (миграции только вперёд, правило 9).
6. **Тестовая инфраструктура** (`backend/tests/conftest.py`, `tests/db.py`):
   - `postgres_url` (session) — `PostgresContainer("postgres:<версия>")` из testcontainers, драйвер asyncpg; один контейнер на прогон.
   - `migrated_db` (session) — `alembic upgrade head` в контейнере.
   - `db_session` (function) — изоляция теста (вопрос 4); `app`-фикстура подменяет `get_session` этой сессией и создаётся с `clock`.
   - `clock` (function) — `FixedClock(datetime(2026, 11, 10, 12, 0, tzinfo=ZoneInfo("Europe/Moscow")))`.
   - Unit-тесты (`tests/unit`) Docker не требуют: контейнер поднимается лениво, только если тест запросил БД.
   - Фабрики — вопрос 5.
7. **`docs/db/schema.sql`** — вопрос 3. **CLAUDE.md** — команды `docker compose … up -d db`, `alembic upgrade head`, `alembic revision --autogenerate -m …`, `alembic check`; Docker нужен для интеграционных тестов.
8. **ADR-0011** «Изоляция тестов БД» + правило в `.claude/rules/tests.md` + `docs/08-testing.md` §5 (AC-11).
9. **Безопасность (AC-10):**
   - `backend/scripts/init_dev_env.py` — один раз создаёт `deploy/.env.dev`: `POSTGRES_USER/DB=zakroma`, `POSTGRES_PASSWORD=secrets.token_urlsafe(32)`, `DATABASE_URL=postgresql+asyncpg://zakroma:<пароль>@127.0.0.1:5432/zakroma`. Существующий файл не перезаписывает, пароль в консоль **не** печатает.
   - `.claude/settings.json`: `deny` для `Read(./**/.env.dev)` (сейчас закрыты только `.env`, `.env.local`, `.env.prod*`).
   - testcontainers: пароль `secrets.token_urlsafe(24)` на прогон, порт привязан к `127.0.0.1`.
   - Логи: при `db_unavailable` пишется только класс исключения, без текста драйвера (он может содержать хост и пользователя); DSN нигде не логируется.
   - Проверка секретов в pre-commit — вопрос 7; prod-БД без опубликованного порта — критерий для T-007 (вопрос 8).
10. **Проектная схема (AC-12):** `git mv docs/db/schema.sql docs/db/schema_design.sql` без правок содержимого; новый `schema.sql` — `pg_dump --schema-only --no-owner` из dev-БД (`docker compose exec db pg_dump`) с короткой шапкой «реализованная схема; проект — в `schema_design.sql`». Обновить ссылки: 04-data-model, rules/database.md, CLAUDE.md (правило 9 и карта документации), `schema_smoke_test.sql`.

Уроки: **L-003** (зависимости — вопрос 6), **L-006** (никакого `DELETE` для очистки — откат/`TRUNCATE`), **L-008**, **L-009** (фикстура `clock`), **L-015/L-016** (PATH для uv и pre-commit в терминале агента).

### 3.6. Риски, альтернативы, вне рамок

- **testcontainers на Windows** — нужен запущенный Docker Desktop; без него интеграционные тесты падают с понятной ошибкой (не пропускаются молча: иначе CI мог бы «зеленеть» без проверок). Первый прогон тянет образ Postgres (~150 МБ).
- **Изоляция через откат** не покрывает код, который сам открывает второе соединение (фоновые задачи S2) — для таких тестов понадобится `TRUNCATE` (L-006); фиксирую в ADR.
- **Соглашение имён = имена Postgres по умолчанию** — если позже понадобится явное имя (как `users_last_household_fk` в `schema.sql`), его задают в модели явно.
- **Вне рамок:** таблицы и модели (T-010, T-011, T-020, T-031); загрузка справочника (T-020); тест миграций «на заполненной БД» (появится, когда будут данные — T-020); Postgres в CI (T-006); prod-compose, `.env.example` (T-007); бэкапы (T-042).

## 5. Решения в ходе реализации

- Версии на 2026-10-23 (`uv.lock`): sqlalchemy 2.1.6 (+ greenlet 3.5.6), asyncpg 0.32.0, alembic 1.20.1; dev — testcontainers 4.15.0 (тянет docker 7.2.0, requests, pywin32). Образ `postgres:18` (18.6). gitleaks v8.30.1.
- **Ryuk отключён** (`testcontainers_config.ryuk_disabled = True`): уборщик testcontainers публикует порт на `0.0.0.0` и `::` — через него из сети можно попросить удалить контейнеры (выявлено проверкой портов, AC-10). Контейнер останавливает фикстура `postgres`; после прогонов лишних контейнеров нет (проверено `docker ps`).
- testcontainers не умеет привязать порт к адресу через API — привязка `("127.0.0.1", None)` записывается прямо в `container.ports` (docker-py это поддерживает); импорт из `testcontainers.community.postgres` (старый путь объявлен устаревшим).
- **Стандартные правила gitleaks не ловят пароль внутри DSN** (проверено на `postgresql+asyncpg://user:<пароль>@…` — Passed). Добавлен `.gitleaks.toml`: стандартные правила + `credentials-in-url` и `password-assignment`, allowlist для шаблонов (`{PASSWORD}`, `${VAR}`, `<…>`) и сгенерированных значений (`secrets.token_urlsafe(…)`). Ложных срабатываний по истории (17 коммитов) и рабочему дереву нет.
- Хук gitleaks на коммите видит только индекс (`--staged`), поэтому `pre-commit run --all-files` историю не проверяет; добавлен ручной этап `gitleaks-history` (`--hook-stage manual`) — его же сможет запускать CI (T-006).
- Тестовые «пароли» генерируются во время прогона (`secrets.token_urlsafe`), а не литералами: ruff `S105` и gitleaks ругались бы на литералы (правило добавлено в `.claude/rules/tests.md`).
- `DATABASE_URL: SecretStr` + `hide_input_in_errors=True`: без этого `ValidationError` при неверной схеме печатает исходное значение с паролем. `extra="ignore"` — в `deploy/.env.dev` лежат и `POSTGRES_*`.
- `deploy/.env.dev` агент не читает: в `.claude/settings.json` добавлены `deny` `Read(./**/.env.dev)` и `Bash(cat *.env*)`. Проверка «пароль не попал в git» сделана сканированием gitleaks (истории и отслеживаемых файлов), а не чтением пароля из файла.
- Соглашение имён `MetaData` = имена Postgres по умолчанию; `CHECK` — `%(constraint_name)s` (без явного имени SQLAlchemy падает уже при создании таблицы — это закреплено тестом).
- ruff: `alembic` объявлен сторонним пакетом (`known-third-party`) — каталог `backend/alembic/` с миграциями путал сортировку импортов; в `alembic/versions/*` разрешён неиспользуемый `import sqlalchemy as sa` из шаблона (нужен автогенерации).
- Тесты, которые сами создают приложение, используют `tests.http.serve(app)` с запущенным lifespan: `httpx.ASGITransport` lifespan не запускает, незакрытый пул давал `ResourceWarning` (= ошибка при `-W error`).
- Модули `test_errors.py` и `test_request_context.py` теперь расширяют общую фикстуру `app` (`def app(app)`) вместо своей — изменена только подготовка, проверки не тронуты. В `test_config.py` добавлена установка `DATABASE_URL` в окружение (поле стало обязательным по AC-3), `test_health.py::test_docs_are_hidden_in_prod` берёт настройки из фикстуры; ожидание `test_health_returns_ok` изменено по согласованию.
- coverage: `concurrency = ["greenlet", "thread"]` — SQLAlchemy async работает на greenlet, и без этого строки после `await session.execute` отмечались непокрытыми (так выглядел `return` в health).
- Таймаут проверки БД перенесён внутрь `app/db/health.py::ping` — роутер стал проще.
- Дамп `schema.sql` снимается с `--restrict-key=zakroma`: pg_dump 18 иначе вставляет случайный ключ `\restrict` и файл меняется при каждом снятии. Перенос проектной схемы — отдельным коммитом (`6b8daa6`, 100 % rename, тот же blob), чтобы история это показывала явно.
- Тест `test_shared_test_database_is_migrated` и тесты изоляции/loopback написаны вместе с фикстурами и сразу зелёные; изоляция дополнительно проверена на заведомо сломанной фикстуре — тест падает (`'probe_isolation' is None`).
