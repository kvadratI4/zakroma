## 1. Описание (оператор)

Из BACKLOG: ручной выбор темы «Как на устройстве» (по умолчанию) / «Светлая» (гжель) / «Тёмная» (хохлома, «Графит»); выбор хранится на устройстве; тема применяется до загрузки JS.

Сводка 02, п. 4 (оператор, 2026-10-28): в T-009 меню разделов в коде приводится к 10-design §6, а переключатель ставится в раздел «Настройки».

## 2. Критерии приёмки (из BACKLOG, T-009)

- **AC-1. Три варианта:** «Как на устройстве» (по умолчанию; тема следует за системной, в том числе при смене во время работы), «Светлая», «Тёмная»; подписи — через i18n.
- **AC-2. Переключатель** видимый (не жест, L-010), доступен с клавиатуры и экранному диктору (текущий вариант озвучивается), зона нажатия ≥ 44 px; место — «Настройки → Мои настройки → Оформление».
- **AC-3. Хранение на устройстве** (`localStorage`), не в учётной записи: выбор переживает перезагрузку; без доступа к `localStorage` (приватный режим) — «Как на устройстве», без ошибок.
- **AC-4. Тема до загрузки JS:** токены `--zk-*` и сохранённый выбор применяются до запуска приложения — ни при тёмной системной, ни при выбранной вручную теме не мелькает белый экран (из T-040).
- **AC-5. Цвета** — только из `tokens.ts`; контраст обеих тем уже проверен (`tokens.test.ts`), новые токены — с тем же тестом.
- **AC-6. CSP** prod-стека остаётся без `unsafe-inline`; smoke-проверка CSP и проверка в браузере — без нарушений (T-007, ADR-0012). Способ — отдельный файл скрипта темы из `/assets/` при прежнем `script-src 'self'` (вопрос 1, ответ а); BACKLOG и ADR-0012 уточняются.
- **AC-7. Меню разделов** приведено к 10-design §6: «Запасы · Всегда дома · ＋ Добавить · Сроки · Настройки» (порядок, названия, маршруты, ключи i18n); экран-заглушка «Настройки» с группой «Мои настройки → Оформление» (сводка 02, п. 4).

## 3. Предложение (агент, `/task-start`)

### 3.1. Понимание задачи

Сейчас тема всегда следует за системной, а цвета ставит JS после загрузки: при тёмной системной теме на медленной сети сначала видна белая страница. Нужно, чтобы человек мог сам выбрать «Светлое» или «Тёмное» оформление (например, бабушке тёмная тема телефона мешает читать) и чтобы правильные цвета были с первой отрисовки. Заодно меню приводится к согласованному виду, иначе переключателю негде стоять: раздела «Настройки» в коде ещё нет, есть «Семья».

### 3.2. Подход

**Эксперимент до предложения (L-017), страница с заголовком CSP из `deploy/Caddyfile`, Chrome встроенного браузера:**

| Случай | Цвет фона до запуска JS приложения | Нарушения CSP |
|---|---|---|
| Система тёмная, выбора нет — только CSS (медиазапрос) | `#1f2226` («Графит») | нет |
| Система тёмная, выбрано «Светлое» — внешний скрипт `/assets/…js` | `#ffffff`, `data-theme="light"` | нет |
| Система тёмная, выбрано «Светлое» — встроенный скрипт по хешу | `#ffffff`, `data-theme="light"` | нет (встроенный скрипт без хеша заблокирован — CSP действует) |
| Система светлая, выбрано «Тёмное» — внешний скрипт | `#1f2226`, `data-theme="dark"` | нет |

Сборка Vite (8.3.5) в отдельной копии:

- CSS из виртуального модуля попадает в общий `index-*.css` и подключается `<link>` в `<head>` — цвета есть до JS;
- **классический `<script src>` Vite не собирает и не копирует** («can't be bundled without type="module"») — файл молча пропадает из `dist`. Значит, скрипт темы нужно выпускать своим маленьким плагином сборки, а не просто ссылкой в `index.html`.

**Предлагаемая реализация:**

1. **Токены — CSS-файлом при сборке, а не из JS.** Маленький плагин Vite в `frontend/plugins/themePlugin.ts` отдаёт виртуальный модуль `virtual:theme.css` из `themeCss()` (`tokens.ts` остаётся единственным источником). `main.tsx` импортирует его вместо `adoptedStyleSheets`. В `themeCss()` добавляется блок `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { …тёмные… } }` — «Как на устройстве» работает до JS и даже без JS.
2. **Сохранённый выбор — крошечный скрипт в `<head>`** (~150 байт): читает `localStorage["zakroma.theme"]`, при `light`/`dark` ставит `data-theme` на `<html>`, ошибки доступа к хранилищу глотает. Источник — функция в `src/shared/theme/themeBoot.ts` (тестируется в jsdom). Как подключить — вопрос 1; рекомендую внешний файл `/assets/theme-boot-<хеш>.js`, который плагин выпускает при сборке и вставляет в начало `<head>` (в dev — тот же текст, dev-сервер без CSP).
3. **Выбор в приложении** — `src/shared/theme/themeChoice.ts`: чтение и запись с защитой от недоступного хранилища; хук `useThemeChoice()` на `useSyncExternalStore` (выбор, системная тема, событие `storage` — смена в другой вкладке тоже применяется). `data-theme` на `<html>` всегда равен действующей теме. Хук `useSystemTheme` остаётся источником системной темы и больше не пишет `data-theme` сам (вопрос 3).
4. **Переключатель** — `SegmentedControl` из T-008b (нативные `radio`: клавиатура, озвучивание выбранного, 44 px), как на согласованном макете «Мои настройки» (`docs/design/screens.html`): подпись «Оформление», варианты «Как на устройстве / Светлое / Тёмное» (вопрос 2).
5. **Меню и разделы (AC-7).** `NAV_ITEMS`: Запасы (`/`) · Всегда дома (`/always`, значок «сумка», как на макете) · ＋ Добавить · Сроки (`/expiry`) · Настройки (`/settings`, значок «шестерёнка»). Экраны-заглушки переименовываются: `features/shopping` → `features/always`, `features/family` → `features/settings`. Экран «Настройки» — заголовок, группа «Мои настройки» с «Оформлением» и строка «Остальные настройки появятся позже» (участники, места, дом — T-015). Старые адреса `/shopping` и `/family` не перенаправляются: приложением ещё никто не пользуется.
6. **Prod.** CSP в Caddyfile не меняется (при варианте 1а). Smoke: новая проверка — в `index.html` скрипт темы стоит в `<head>` раньше скрипта приложения, сам файл отдаётся из `/assets/` с годовым кэшем и типом JavaScript. Проверка глазами в Chrome на prod-стеке: обе системные темы × три варианта, 0 нарушений CSP (`securitypolicyviolation`).
7. Витрина `/dev/ui` сохраняет свой переключатель темы (он меняет `data-theme` только на время просмотра витрины).

### 3.6. Риски, альтернативы, вне рамок

- **Лишний запрос в `<head>` (вариант 1а).** Скрипт загружается параллельно с CSS (оба в `<head>`, одно соединение HTTP/2), после первого раза — из кэша навсегда (имя с хешем). Задержка первой отрисовки — не больше, чем от уже существующего CSS. С service worker (T-040) — ноль запросов.
- **Dev-режим:** в `pnpm dev` CSS вставляет JS, поэтому в dev белая вспышка возможна — CSP там нет, на prod не влияет.
- **Узкий экран:** три варианта в одну строку («Как на устройстве / Светлое / Тёмное») на 320 px могут не поместиться — проверить глазами; запасной вид — `RadioList` (столбик).
- **Вне рамок:** остальное содержимое «Настроек» (участники, места, дом, ревизия) — T-015 и T-039; цвет строки состояния браузера (`theme-color`) — T-040 (манифест); хранение выбора в учётной записи — не делаем (решение: на устройстве).
- Применимые уроки: L-010 (видимый переключатель), L-017 (эксперимент выше), L-019 (подготовка трёх существующих тестов перечислена), L-029 (проверки сборки и smoke — с обратным опытом), L-041 (CSP проверяется в prod-сборке).

## 5. Решения в ходе реализации

- **Плагин сборки — `frontend/plugins/`, а не `frontend/build/`:** каталоги `build/` игнорируются общим правилом `.gitignore` (сборка Python); переименование проще исключения из правила.
- **Скрипт темы — первым в `<head>`, раньше `<meta charset>`** (`injectTo: "head-prepend"`): объявление кодировки остаётся в первых 1024 байтах, а скрипт гарантированно выполняется до разбора `<body>`. В имени файла — первые 8 знаков sha256 текста скрипта.
- **В dev скрипт встроен в `index.html`** тем же текстом: у dev-сервера нет CSP, отдельный файл не нужен.
- **`OptionGroup` (T-008b) — колонка `minmax(0,1fr)` и перенос длинного варианта по центру, отступы сегментов 12 px вместо 16 px:** без этого три варианта «Оформления» на телефоне шире 380 px выходили за край экрана; правка общая — «По местам / По видам» выглядят так же.
- **Существующий smoke `test_hashed_assets_are_cached_and_compressed`** берёт теперь скрипт приложения (`type="module"`), а не первый скрипт из `/assets/`: первым стоит скрипт темы (~130 байт), а Caddy не сжимает ответы меньше 512 байт. Строгость проверки та же; скрипт темы проверяет новая `test_theme_is_applied_before_the_app`. Оператор (2026-10-28), после разбора вариантов (другой порядок скриптов, файл вне `/assets/`, сжатие мелких файлов, встроенный скрипт по хешу): «согласен на рекомендованный вариант».
- **Адреса** `/always` и `/settings` (вопрос 4); значок «Всегда дома» — сумка, «Настройки» — шестерёнка, как на макете; значок `family` остаётся в наборе (участники дома, T-015).
