## 2. Критерии приёмки (согласованы оператором 2026-10-25)

  - Базовые образы закреплены по digest (вопрос 5), есть `.dockerignore`.
- **AC-2. Compose одной командой.** `deploy/docker-compose.yml`: `docker compose up -d --wait` поднимает стек:

  - gitleaks зелёный.
- **AC-5. Caddy.**

## 3. Предложение (агент, `/task-start`)

### 3.1. Понимание задачи

Нужна prod-конфигурация, которую можно поднять одной командой: сначала у оператора на машине, потом без изменений на VPS (T-041). Стек — Caddy (HTTPS, SPA, прокси API, заголовки безопасности), api, Postgres и миграции.

Главные требования — безопасность по умолчанию:

- база не видна снаружи, а api ходит в неё ролью без права менять схему;
- секреты есть только в серверном `.env`;
- браузер получает строгий CSP;
- OpenAPI-схема в prod закрыта.

Бэкапы (T-042), выбор VPS и деплой из CI (T-041) в задачу не входят.

### 3.2. Подход

Подход проверен прототипом в черновой копии (§3.6).

**Образ api** (`backend/Dockerfile`):

- uv 0.13.5 копируется из официального образа;
- `uv sync --frozen --no-dev --no-install-project` в стадии сборки, Python — из базового `python:3.13-slim`, без скачивания;
- в итоговом образе — `.venv`, `app`, `alembic`, пользователь uid 10001;
- команда: `uvicorn app.main:create_app --factory --host 0.0.0.0 --proxy-headers --forwarded-allow-ips 172.30.250.0/24 --workers 2`.

**Образ caddy** (`deploy/caddy.Dockerfile`, контекст — корень репозитория):

- стадия `node:24-alpine`: corepack → `pnpm install --frozen-lockfile` → `pnpm build`;
- стадия `caddy:2-alpine` (2.11.7): `Caddyfile` и `dist` → `/srv/web`.

**Compose** (`deploy/docker-compose.yml`, имя проекта `zakroma`):

| Сервис | Сети | Главное |
|---|---|---|
| `db` | `db` (internal) | `postgres:18@sha256:…`; том `pgdata`; `docker-entrypoint-initdb.d/10-roles.sh` создаёт роли при первой инициализации тома; без `ports` |
| `migrate` | `db` | образ api, `alembic upgrade head`, `DATABASE_URL` владельца; `api` ждёт `service_completed_successfully` — миграции всегда до нового кода (09-deployment §4) |
| `api` | `web`, `db` | `DATABASE_URL` роли приложения, `ENVIRONMENT=prod`; `read_only`, `tmpfs /tmp`, `cap_drop: [ALL]`, `no-new-privileges`; healthcheck `/api/v1/health` |
| `caddy` | `web` | порты `${HTTP_BIND:-80}:80`, `${HTTPS_BIND:-443}:443` (+ `443/udp` для HTTP/3); тома `caddy_data`, `caddy_config` |

- Сеть `web` — с фиксированной подсетью `172.30.250.0/24`: на неё ссылается `--forwarded-allow-ips`.
- Сеть `db` — `internal: true`: Caddy до базы не достаёт, у базы нет выхода в интернет.
- Каждому сервису передаются только нужные переменные: ни у кого нет всего `.env` целиком.

**Роли БД** (вопрос 1, скрипт `deploy/db-init/10-roles.sh`):

- создаёт `zakroma_owner` (LOGIN, не суперпользователь) и `zakroma_app`;
- создаёт базу `zakroma` с владельцем `zakroma_owner`;
- `REVOKE CONNECT ON DATABASE postgres FROM PUBLIC`;
- даёт `zakroma_app` `CONNECT` и `USAGE`, а также `ALTER DEFAULT PRIVILEGES FOR ROLE zakroma_owner …`: SELECT/INSERT/UPDATE/DELETE на таблицы, USAGE/SELECT на последовательности.
- Пароли попадают в SQL переменными `psql` (`:'owner_pw'`) — без подстановки в текст запроса.

Интеграционный тест `tests/integration/test_db_roles.py` поднимает отдельный Postgres (testcontainers) с **тем же** скриптом и проверяет:

- `alembic upgrade head` от `zakroma_owner` проходит;
- `zakroma_app` читает и пишет, но `CREATE TABLE`, `DROP` и подключение к `postgres` запрещены;
- обе роли — не суперпользователи.

**Секреты** (L-018):

- `init_prod_env.py --site-address <домен|127.0.0.1>` пишет `deploy/.env`: три пароля `secrets.token_urlsafe(32)` и `SITE_ADDRESS`; для `127.0.0.1` ещё `HTTP_BIND=127.0.0.1:8080` и `HTTPS_BIND=127.0.0.1:8443`;
- файл открывается в режиме `x`, `chmod 600`, значения не печатаются; тесты — по образцу `test_init_dev_env.py`;
- `.env.example` перечисляет переменные без значений.

**Caddy** (`deploy/Caddyfile`):

- `admin off`; `default_sni {$SITE_ADDRESS}` — по IP-адресу клиент не шлёт SNI;
- `encode zstd gzip`; `request_header X-Request-ID {http.request.uuid}`;
- `handle /api/*` → `reverse_proxy api:8000`; иначе `try_files {path} /index.html` + `file_server`;
- кэш: `/assets/*` — `public, max-age=31536000, immutable`, остальное — `no-cache`;
- заголовки:
  - `Strict-Transport-Security: max-age=31536000`;
  - `X-Content-Type-Options: nosniff`;
  - `Referrer-Policy: same-origin`;
  - `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()` — камеру для сканера включит S2;
  - убран `Server`;
- CSP: `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'`.

**CSP и токены темы** (вопрос 3). Сейчас `main.tsx` вставляет токены темы элементом `<style>`, и строгий `style-src 'self'` его блокирует: страница без цветов (проверено). Правка на одну строку: конструируемая таблица стилей (`new CSSStyleSheet()` + `replaceSync` + `document.adoptedStyleSheets`) идёт через CSSOM, а его CSP не ограничивает. Под строгим CSP — ноль нарушений, тема применяется (проверено в Chrome). T-009 позже перенесёт токены в сборку (тема до загрузки JS); скрипт темы там разрешится в CSP по хешу.

**OpenAPI в prod** (AC-6): в `create_app` при `ENVIRONMENT=prod` — `openapi_url=None` (Swagger уже выключен).

- `app.openapi()` от маршрута не зависит: экспорт строит приложение в `environment="test"`, клиент генерируется как прежде.
- В `test_docs_are_hidden_in_prod` проверка схемы меняется на `404` (согласовано оператором).

**Smoke-проверка** (вопрос 7): `backend/tests/smoke/test_prod_stack.py`. Модуль пропускается, если не задан `ZAKROMA_SMOKE_URL`, поэтому обычный `pytest` его не запускает.

- TLS проверяется корневым сертификатом внутреннего CA Caddy: `docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt`, путь — в `ZAKROMA_SMOKE_CA`. Без `verify=False`.
- Проверки — по AC-8. Порт БД — через `docker compose port db 5432`: ожидается пусто.

**CI** (вопрос 4): задача `prod-stack` — `init_prod_env.py --site-address 127.0.0.1` → `docker compose build` → `up -d --wait` → smoke → `down -v`. Кэш слоёв — `docker/build-push-action` не нужен: обычный `compose build` около 1,5 минуты.

**Закрепление образов и Dependabot** (вопрос 5): все базовые образы по digest с тегом в комментарии; в `dependabot.yml` добавить экосистемы `docker` (`/backend`, `/deploy`) и `docker-compose` (`/deploy`) — обновляет digest, PR проходит CI вместе с `prod-stack`.

**`@types/node`** (вопрос 6): Dependabot предложил major-версию (24 → 26), PR #7 принят. В T-004 типы сознательно держали под Node 24, на котором работают разработка, CI и сборка (`.nvmrc`). С типами 26 TypeScript не остановит использование API, которого в Node 24 нет. Предлагаю вернуть `^24` и добавить в `dependabot.yml` `ignore` для major-версий `@types/node`; при переходе на Node 26 их снимут вместе с `.nvmrc`.

### 3.6. Риски, альтернативы, вне рамок

**Проверено прототипом (L-017, L-034).** Черновая копия `git archive HEAD` и черновые Dockerfile, compose и Caddyfile — в черновой папке. Секреты сгенерированы там же и удалены вместе с контейнерами, томами и образами.

- **Роли:** `zakroma_owner` без прав суперпользователя выполняет `CREATE EXTENSION pg_trgm` (доверенное расширение с PG13) и создаёт таблицы. `zakroma_app` читает и пишет, на `CREATE TABLE` получает `permission denied for schema public`, на `DROP` — `must be owner`. По умолчанию app могла подключиться к служебной базе `postgres` → `REVOKE CONNECT … FROM PUBLIC`.
- **Сборка:** 79 с с нуля; образ api — 270 МБ, caddy со SPA — 94 МБ.
- **Запуск:** `up -d --wait` — 21 с; migrate прошёл раньше api; все сервисы healthy; у `db` порт не опубликован; снаружи слушает только `127.0.0.1:8443`.
- **Память:** api с 2 воркерами — 152 МБ, Postgres — 42 МБ, Caddy — 15 МБ; итого около 210 МБ при VPS 2 ГБ.
- **Caddy:**
  - health через Caddy — 200 с `X-Request-ID`, подменённый клиентом id заменён;
  - прямая ссылка `/shopping` → 200 `text/html`;
  - все заголовки на месте; `/assets/*` — `immutable` и `zstd`;
  - у `index.html` не было `Cache-Control` → в план добавлен `no-cache`, иначе обновления SPA будут застревать в кэше;
  - **первая попытка TLS не удалась:** клиенты не шлют SNI для IP-адреса, Caddy не выбирал сертификат → `default_sni`.
- **HSTS и `localhost`:** HSTS действует на хост без учёта порта. Локальный запуск на `https://localhost` заставил бы браузер открывать по HTTPS **все** локальные проекты на `localhost`. На IP-адреса HSTS не распространяется → `https://127.0.0.1:8443`.
- **CSP:** со строгим `style-src 'self'` Chrome отклонил вставку `<style>` с токенами (`Applying inline style violates … 'style-src 'self''`). С `adoptedStyleSheets` — 0 нарушений, тема применена (снимок 390 px).
- **OpenAPI в prod:** сейчас `openapi.json` → 200, `docs` → 404 — подтверждает AC-6.
- **uvicorn 0.54:** `--forwarded-allow-ips` принимает подсети (`ipaddress.ip_network` в `ProxyHeadersMiddleware`).
- **Dependabot (TC-8 из T-006):** после merge отработал по всем трём экосистемам (`github_actions`, `uv`, `npm_and_yarn` — success), lock-файл pnpm 12 понимает. Предложил `@types/node` 26 → вопрос 6.

**Риски:**

- **Внутренний CA Caddy** при локальном запуске: браузер один раз предупредит о сертификате. Можно установить корневой сертификат из тома `caddy_data` — шаги в 09-deployment.
- **`10-roles.sh` срабатывает только на пустом томе** (поведение образа Postgres). Существующих prod-данных пока нет, а смена паролей и ролей позже — ручная процедура, будет описана в 09-deployment.
- **Фиксированная подсеть** `172.30.250.0/24` может пересечься с сетью на VPS — проверка в T-041. Подсеть задаётся в одном месте.
- **Время CI** вырастет примерно на 2 минуты (параллельная задача, общая длительность — около 2–3 минут).

**Альтернативы:**

- `style-src 'unsafe-inline'` вместо правки `main.tsx` — слабее и противоречит критерию.
- Роли через миграцию Alembic — смешивает уровень кластера с уровнем схемы, а пароль попал бы в миграцию.
- Сервис `web` с nginx — лишний контейнер: Caddy раздаёт статику сам (09-deployment).
- `hadolint` для Dockerfile — новый инструмент, не предлагаю сейчас.

**Вне рамок:**

- бэкапы (T-042);
- VPS, домен, GHCR и деплой (T-041);
- тема до загрузки JS (T-009);
- `manifest` и service worker (T-040);
- E2E (T-043) — он будет проверять отсутствие нарушений CSP в каждом сценарии.

**Применимые уроки:** L-003, L-017, L-018, L-021, L-022, L-025, L-029, L-032, L-033, L-034.

## 5. Решения в ходе реализации

- **`init_prod_env.py`:** адрес сайта проверяется до записи — только имя хоста или IPv4, без схемы и порта. Значение попадает и в `.env`, и в адрес сайта Caddy, а перевод строки позволил бы дописать свою переменную. Файл создаётся `os.open(..., O_EXCL, 0o600)` — нет момента, когда он доступен другим. Тест сверяет набор переменных с `.env.example`, а в самом примере значения пустые.
- **Тест ролей** поднимает свой Postgres с `deploy/db-init` через `with_volume_mapping` и проверяет SQLSTATE `42501` на каждой запрещённой операции. Первая версия на `asyncpg` не прошла mypy (у пакета нет аннотаций типов), а коммит всё равно прошёл: код выхода mypy потерялся в `| tail` (L-029). Исправлено следующим коммитом `ea21b0b`, история не переписывалась.
- **Compose:** общий фрагмент `x-hardening` (`no-new-privileges`, логи по 3 × 10 МБ); у `db` нет `cap_drop`: entrypoint Postgres меняет владельца каталога и переключает пользователя. У `api` — `pull_policy: never`: образ собирает `migrate`, а без этого compose искал `zakroma-api` в Docker Hub (`pull access denied` в выводе). Реестр образов — в T-041.
- **Caddy:**
  - `default_sni` — по IP-адресу клиенты не шлют SNI, без этого TLS не устанавливался;
  - `skip_install_trust` — убирает попытку поставить корневой сертификат в хранилище доверия внутри контейнера и предупреждение о пароле в логе;
  - `Cache-Control: no-cache` для всего, кроме `/assets/*` и `/api/*`;
  - `-Server` убирает и заголовок `server: uvicorn` от api.
- **Лимит тела запроса** (найдено при проверке безопасности стека, в AC его не было). Сначала был только `request_body max_size 1MB`, но тест показал 405: лимит срабатывает, лишь когда upstream читает тело, а api отвечает на неподходящий метод не читая. Добавлена ранняя проверка `header_regexp Content-Length ^[0-9]{7,}$` → `413` problem+json `payload_too_large`, до api запрос не доходит. В `06-api.md` — новая строка в таблице ошибок.
- **Пересоздание контейнеров:** после пересборки без изменений кода образ получил новый ID, а контейнеры остались на прежнем, хотя содержимое то же. При реальном изменении кода compose пересоздал и `migrate`, и `api` на новом образе — проверено. Почему ID меняется без изменений, не выяснено до конца; в документации правило — обновлять стек целиком, без имени сервиса.
- **Smoke-тест образов** проверяет образы по имени из `docker compose config --images`: в хранилище containerd у Docker Desktop `docker image inspect <ID из compose images>` образ не находил.
- **`@types/node`** возвращён на `^24.19.2`. Первый `pnpm add` завис на скрытом вопросе: без TTY pnpm ждал ответа — повтор с `CI=true` и ограничением по времени.
- **Dependabot:** экосистемы `docker` (`/backend`, `/deploy`) и `docker-compose` (`/deploy`), major-версии образов игнорируются; файл проверен по схеме.
- **ADR-0012** — минимальные права в prod-стеке; правила агента — `.claude/rules/deploy.md`.
