- **AC-6.** Логи — JSON в stdout (structlog); у каждого запроса `request_id` во всех строках лога и в заголовке ответа `X-Request-ID`; одна строка доступа на запрос (метод, путь, статус, длительность).
- **AC-7.** Настройки читаются из переменных окружения через `pydantic-settings`; неверное значение → ошибка при старте, а не в момент запроса.
- **AC-8.** `Clock`: протокол с `now() -> datetime` (всегда с tzinfo), реализации `SystemClock` и `FixedClock`; доступен через зависимость FastAPI и подменяется в тестах.
- **AC-9.** `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy app` (strict) — без ошибок; `uv run pytest` зелёный, покрытие `app` ≥ 80 %.

## 3. Предложение (агент, `/task-start`)

### 3.1. Понимание задачи

Создать минимальное, но «правильное» backend-приложение, на которое дальше навешиваются БД (T-003), аутентификация (T-010) и доменный слой (T-030): структура пакетов из architecture §4, единый формат ошибок, структурные логи с идентификатором запроса, типизированные настройки, инжектируемое время и полный набор проверок качества (ruff, mypy strict, pytest с покрытием). Единственный «бизнес»-эндпоинт — health. Всё, что пишут следующие задачи, должно сразу попадать в эти рамки, а не изобретать свои.

### 3.2. Подход

1. **Проект uv** в `backend/`: `pyproject.toml` (приложение, не пакет: `[tool.uv] package = false`), `uv.lock`, `.python-version`. Конфиги ruff, mypy, pytest, coverage — в том же `pyproject.toml`.
   - ruff: правила из CONVENTIONS (`E, F, I, B, UP, SIM, RUF, ASYNC, S`), `line-length = 100`, в `tests/` разрешён `assert` (S101).
   - mypy: `strict = true` + плагин pydantic.
   - pytest: `asyncio_mode = "auto"`, `--strict-markers`; coverage `fail_under = 80` по `app`, с ветвлениями.
2. **Структура** (только то, что нужно сейчас; пустые слои `domain/`, `db/`, `services/`, `integrations/` создадут их задачи):
   ```
   backend/app/main.py            # create_app(settings) — фабрика, uvicorn --factory
   backend/app/core/config.py     # Settings (pydantic-settings), get_settings()
   backend/app/core/clock.py      # Clock (Protocol), SystemClock, FixedClock
   backend/app/core/errors.py     # AppError, problem+json обработчики
   backend/app/core/logging.py    # structlog: JSON/console, stdlib → structlog
   backend/app/core/middleware.py # RequestContextMiddleware (request_id, access-лог)
   backend/app/api/deps.py        # get_clock, get_settings (зависимости)
   backend/app/api/v1/router.py   # общий роутер /api/v1
   backend/app/api/v1/health/{router,schemas}.py
   ```
3. **Фабрика** `create_app(settings: Settings | None = None)`: без побочных эффектов при импорте — тесты создают приложение со своими настройками. `openapi_url="/api/v1/openapi.json"`, `docs_url="/api/v1/docs"` — только если `environment != "prod"`.
4. **Настройки** — без префикса переменных (как в 09-deployment: `DATABASE_URL`, `SESSION_SECRET`): `ENVIRONMENT` (`dev|test|prod`, по умолчанию `dev`), `LOG_LEVEL` (по умолчанию `INFO`), `LOG_FORMAT` (`json|console`, по умолчанию `json`). `DATABASE_URL` добавит T-003, `SESSION_SECRET` — T-010.
5. **Ошибки** (`core/errors.py`): `AppError(code, status, title, detail=None, **extra)`; один формат тела: `type = "https://zakroma/errors/<code-через-дефис>"` (как пример в architecture), `title` — по-русски (как в примере architecture; UI всё равно переводит `code`), `status`, `code`, `detail`, плюс доп. поля (`current` для 409 в будущем). Обработчики: `AppError`, `RequestValidationError` (422; из каждой ошибки pydantic оставляем только `loc`, `type`, `msg` — `input`/`ctx` выбрасываем, чтобы не вернуть пароль), `StarletteHTTPException` (404/405 → `not_found`/`method_not_allowed`), `Exception` (500, `internal_error`, трассировка — только в лог).
6. **Логи** (`core/logging.py`): structlog с `contextvars`, `TimeStamper(iso, utc)`, `JSONRenderer` (или `ConsoleRenderer` при `LOG_FORMAT=console`); стандартный `logging` (uvicorn, библиотеки) пропускаем через тот же форматтер — все строки одного вида. Персональных данных в логах нет: логируется путь без query-строки.
7. **Middleware** — чистый ASGI (не `BaseHTTPMiddleware`: тот ломает contextvars и стриминг): берёт `X-Request-ID` из запроса, если он безопасный (`^[A-Za-z0-9._-]{1,64}$`), иначе генерирует `uuid4().hex`; кладёт в contextvars structlog; добавляет заголовок в ответ; пишет `http_request` (method, path, status, duration_ms).
8. **Clock** (`core/clock.py`): `Protocol` с `now() -> datetime`; `SystemClock` → `datetime.now(UTC)`; `FixedClock(at)` требует aware-datetime (иначе `ValueError`), есть `advance(timedelta)` для будущих тестов сроков. Экземпляр живёт в `app.state.clock`, зависимость `get_clock` в `api/deps.py`; в тестах — `FixedClock`. Фикстура `clock` (2026-11-10 12:00 Europe/Moscow) — в T-003 по BACKLOG; здесь только тип и реализация. Нужен `tzdata`: на Windows без него `ZoneInfo("Europe/Moscow")` падает (нет системной базы часовых поясов).
9. **Команды** в CLAUDE.md: запуск dev-сервера `uv run uvicorn app.main:create_app --factory --reload`, тесты с покрытием; разрешения в `.claude/settings.json` (AC-2).

Уроки: **L-003** (зависимости — вопрос 2), **L-009** (время только через `Clock`), **L-012** (никаких внешних API), **L-014/L-016** (на Windows `python`, uv по явному пути в терминале агента).

### 3.6. Риски, альтернативы, вне рамок

- **Без БД health «врёт» наполовину** — отвечает `ok`, даже если БД нет; честная проверка появится в T-003 (там же `503` при недоступной БД).
- **structlog + stdlib + uvicorn** — частая точка путаницы с двойными логами. Митигация: TC-12 проверяет, что каждая строка stdout — один JSON; access-лог uvicorn отключается при запуске (`--no-access-log`, наш middleware пишет свой).
- **Тестовые роутеры** в тестах, а не флаг в приложении — продовый код не содержит «отладочных» путей.
- **Docker на машине не установлен** — для T-002 не нужен, но T-003 (testcontainers, Postgres) без него не пойдёт; стоит поставить Docker Desktop заранее.
- **Вне рамок:** БД, сессии, Alembic, фикстура `clock` и фабрики (T-003); CORS и проверка `Origin` (T-010; frontend ходит через тот же origin — Vite proxy/Caddy); Dockerfile и параметры uvicorn в проде (T-007); экспорт OpenAPI в файл (T-005); доменный слой и тест «domain не импортирует FastAPI» (T-030); Sentry/GlitchTip.

## 5. Решения в ходе реализации

- Версии на 2026-10-23 (`uv.lock`): fastapi 0.161.1, starlette 1.9.0, pydantic 2.14.1, pydantic-settings 2.16.1, structlog 26.1.0, uvicorn 0.54.0, tzdata 2026.5; dev — ruff 0.17.2, mypy 2.4.0, pytest 9.1.1, pytest-asyncio 1.4.0, pytest-cov 7.1.0, httpx 0.28.1. Python 3.13.12 (системный, `.python-version` = 3.13).
- ruff: отключены `RUF001–RUF003` («похожие символы») — в проекте русские строки, кириллица давала ложные срабатывания.
- `Settings` неизменяемые (`frozen=True`), `.env`-файл не читается: в проде переменные даёт Docker Compose, локально хватает значений по умолчанию.
- Необработанные исключения превращает в `500` сам `RequestContextMiddleware`, а не обработчик `Exception` в FastAPI: обработчик Starlette для `Exception` срабатывает снаружи middleware — без `request_id` в логе и без заголовка `X-Request-ID`, а исключение потом повторно логирует uvicorn.
- Access-лог uvicorn отключён в `configure_logging` (`uvicorn.access.disabled`): флаг `--no-access-log` не помогает — фабрика перенастраивает логгеры после uvicorn (выявлено smoke-запуском, закреплено тестом `test_uvicorn_logs_are_json_but_its_access_log_is_off`).
- Логгеры `httpx`/`httpcore` подняты до WARNING: на INFO они пишут полный URL с query (тест поймал `token=s3cret` из лога тестового клиента; в S2 так же утекли бы ключи внешних API).
- Обработчик логов пишет в *текущий* `sys.stdout` (`_StdoutHandler`) — иначе захват вывода в тестах зависит от порядка фикстур.
- Обработчики ошибок используют `cast` вместо `assert isinstance`: реестр Starlette типизирован `Exception`, а `assert` в `app/` запрещён правилом `S101`.
- Тестовые («пробные») роутеры называются `probe_router`: имя `test_router` pytest пытается собрать как тест.
- Тест `test_console_format_is_human_readable` был зелёным сразу — он покрывает уже написанную ветку `LOG_FORMAT=console`, а не новое поведение; оставлен ради покрытия.
- Хуки ruff в pre-commit вызывают `uv`; в терминале агента uv не в PATH (L-016) — коммиты агента идут с явным PATH. У оператора uv в PATH есть.
