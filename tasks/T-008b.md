## 3. Предложение (агент, `/task-start`)

### 3.1. Понимание задачи

Нужно собрать «кирпичики», из которых в T-008c и задачах E1–E3 будут сложены экраны с согласованных макетов: кнопки, поля, счётчик, выбор уровня, переключатели, значки и роспись. Каждый кирпичик сразу соблюдает правила для старших — крупная цель нажатия, подпись словом, видимый фокус, понятное имя для экранного диктора — и проверяется тестами, чтобы ошибка доступности не дошла до экранов. Заодно в код переходит выбранная тёмная тема «Графит». Оператор смотрит готовые компоненты на странице `/dev/ui`, которой нет в рабочем приложении.

### 3.2. Подход

**Главное решение — нативные элементы вместо Radix в базовых компонентах.** Эксперимент (ниже) показал: под нашим строгим CSP безопасны только простые примитивы Radix, а их нативные аналоги дают то же самое без зависимости:

| Компонент | Основа | Почему |
|---|---|---|
| LevelPicker, ChoiceChips, SegmentedControl, RadioList | группа `<input type="radio">` в `<fieldset>`, оформленная подписью-кнопкой | стрелки, Tab и озвучивание «выбрано, 3 из 6» браузер даёт сам; `axe` не находит нарушений |
| Switch | `<button role="switch" aria-checked>` | 10 строк; Radix Switch ничего не добавляет |
| Select | нативный `<select>` | на телефоне открывает системный список — крупный и привычный старшим; Radix Select нарушает CSP |
| DateField | нативный `<input type="date">` | системный календарь, без зависимости (решено в T-008a) |
| Stepper | своя `role="spinbutton"` с кнопками −/+ | готового нативного аналога с мерами («2 пакета») нет |

Radix остаётся кандидатом только для меню «⋯» в T-008c (немодальный режим проходит CSP); диалог «Покинуть дом» там же — на нативном `<dialog>`. Это решение T-008c, здесь Radix не подключается.

**Порядок работы — по группам, коммит после каждой зелёной:**

1. **Токены «Графит»:** `tokens.ts` (новые значения тёмной темы и уровней, роли `borderControl`, `ornamentLeaf` в обеих темах), `cssVariables.ts`, `index.css` (цвета Tailwind `line-control`, `ornament-leaf`); тесты контраста новых пар.
2. **Инструменты тестов:** помощник `expectAccessible(container)` поверх `axe-core` в `src/test/a11y.ts` (правило контраста в jsdom отключено — цвета там не вычисляются; контраст проверяет `tokens.test.ts`).
3. **Кнопки и поля:** Button, IconButton, ActionPill, TextField, SearchField, Select, DateField; расширение `Icon` (поиск, фильтр, «⋯», закрыть, галочка, предупреждение, часы, календарь, минус, шестерёнка, пригласить, нет сети, стрелки).
4. **Выбор:** Stepper, ChoiceChips, SegmentedControl, RadioList, Switch.
5. **Уровни:** LevelChip, LevelButton, LevelPicker (невыбранные нейтральные, без точки; выбранный — тон уровня и галочка).
6. **Остальное:** Badge, Avatar, Skeleton, ProgressBar, роспись — Emblem по типу места (купавка, снежинка, колос, рябина), Window, Izba; листья Spray — роль `ornamentLeaf`.
7. **Витрина `/dev/ui`:** маршрут подключается только при `import.meta.env.DEV` через ленивый импорт; все компоненты во всех состояниях, переключатель светлой и тёмной темы; тексты витрины — в отдельном словаре, который загружается только вместе с витриной.

**Правила внутри компонентов:** цвета — только классы Tailwind из токенов; размеры и радиусы — из 10-design §7; подписи — из i18n, компоненты принимают уже переведённый текст или ключ; формы числа мер — через i18next plurals (подготовка к 05 §1.1, сами меры приходят в E2); род продукта для «Закончился / Закончилась…» — через i18next context в T-008c.

**Проверено заранее (L-017, L-025)** — эксперимент в копии `frontend` вне репозитория, зависимости проекта не менялись:

- **Radix 1.8.1 под CSP prod-стека** (сборка + сервер с заголовком из `deploy/Caddyfile`, Chrome): Switch и RadioGroup — 0 нарушений; DropdownMenu (модальный), Select и Dialog вставляют элемент `<style>` (`react-remove-scroll`, у Select ещё стиль прокрутки) → нарушение `style-src-elem`, блокировка прокрутки страницы не срабатывает (`overflow: visible`), хотя сам диалог открывается и держит фокус; DropdownMenu с `modal={false}` — 0 нарушений. Стили, которые React ставит через `style={…}`, CSP не нарушают.
- **axe-core 4.14.0** (вышел 2026-10-05, peer-зависимостей нет) в Vitest + jsdom работает: на кнопке с именем, подписанном поле, нативной группе radio и `role="switch"` с `aria-checked` — 0 нарушений; находит кнопку-иконку без имени (`button-name`), поле без подписи (`label`), переключатель без состояния (`aria-required-attr`). Первый прогон в Windows-терминале — около 55 с на окружение jsdom, сами проверки — миллисекунды.
- **Витрина только для dev:** модуль, импортируемый под `if (import.meta.env.DEV)`, не попадает в prod-сборку (маркер-строка не найдена в `dist`, лишнего чанка нет).
- **Размер:** текущий первый экран — 125,9 КБ gzip из 300; базовые компоненты в prod попадут только вместе с экранами, которые их используют.

### 3.5. Изменения контрактов

API — нет. Схема БД — нет. Доменные правила — нет. **Зависимости:** `axe-core` 4.14.0 в devDependencies (вопрос 2); Radix не подключается (вопрос 1). **Существующие тесты:** `cssVariables.test.ts` проверяет старые цвета тёмной темы (`#110d0a`, `#dfa9dd`) — при «Графите» их ожидаемые значения нужно заменить (вопрос 4).

### 3.6. Риски, альтернативы, вне рамок

**Риски:**

- **Стилизация нативных radio и select.** Оформить `<select>` целиком нельзя (открытый список рисует система) — закрытое поле выглядит как на макете, открытый список — системный. Для старших это плюс, для «как на макете» — уступка.
- **Длительность тестов.** Каждый файл с `axe` в jsdom стартует окружение заново; при 20 файлах прогон заметно дольше. Мера: проверки доступности собрать в один файл по списку компонентов (TC-17), поведение — в файлах компонентов.
- **`input type="date"` в старых Safari** показывает простое поле; NFR-PLAT-02 (Safari ≥ 16.4) календарь поддерживает.

**Альтернативы:** Radix Switch/RadioGroup (проходят CSP, но не нужны при нативных элементах); свой выпадающий список вместо `<select>` (больше кода и проверок доступности без выигрыша для старших); Storybook — отклонён в T-008a (вопрос 7).

**Вне рамок:** составные компоненты, меню «⋯», диалог, тост, нижнее меню с «Всегда дома» и «Настройками» (T-008c); экраны с данными (E1–E3); ручной выбор темы (T-009 — витрина переключает тему только для себя).

**Применимые уроки:** L-010 (видимые кнопки), L-017 (эксперимент — выполнен), L-025 (peer-зависимости — проверены), L-026 (`tsc` после изменений), L-029 (RED по правильной причине), L-030 (fetch не нужен — компоненты без сети), L-037 (`pnpm add` с `CI=true`), L-040 (род — в T-008c).

## 5. Решения в ходе реализации

- **Граница контролов в светлой теме — `#8a96ae`**, а не `#c5cfe0` с макета круга 2: принятый критерий AC-1 требует ≥ 2,5:1 к `surface` и `raised`, а `#c5cfe0` даёт 1,4–1,6:1. Новое значение — 2,7:1 к `surface`, 3,0:1 к белому; 10-design §2 обновлён.
- **Проверка росписи:** штрих `ornament` к фону ≥ 3:1 в обеих темах, листья `ornamentLeaf` — только в тёмной (в светлой лист — бледная заливка под штрихом, как `ornamentFill`; роспись декоративна и скрыта от диктора).
