## 1. Описание (оператор)

Из BACKLOG: каркас frontend — Vite + React + TS strict + Tailwind + Router + TanStack Query + i18next (ru) + Vitest + Testing Library + MSW; layout с нижней навигацией (заглушки экранов).

Пожелания оператора к дизайну (2026-10-23, близко к тексту):

> Дизайн — в современном русском стиле, глубокий и эстетичный, сочетающий традиции, тепло и уют дома. Совместить традиционные решения русской культуры с эстетикой громкого застолья: традиционную роспись (гжель или хохлома) с необычными шрифтами. Нравятся большие заголовки в старорусском стиле, как на https://vechestore.ru/. Совместить исторические и современные решения, чтобы получилась гармоничная картина. Дизайн должен выглядеть дорого и премиально.

Уточнение оператора (2026-10-23, близко к тексту):

> Орнаменты — не основной фокус. Основное в дизайне — домашняя обстановка и уют. Необычные шрифты и небольшие элементы-орнаменты — дополнение, а не главный признак, который стягивает всё внимание. Функциональность > дизайн, но неприятный и невдохновляющий дизайн будет отталкивать и меня, и членов семьи. Гармония, эстетика, современный стиль, дороговизна. Отдельная страница для согласования нравится — так проще понять, что я хочу увидеть. Деление светлой и тёмной темы на гжель и хохлому нравится, но нужно посмотреть, как будет выглядеть.

Изучение референса (vechestore.ru, 2026-10-23): заголовки — заглавные буквы в духе устава (шрифт `oldcyrylic`, ~72px), слово-логотип «ВЕЧЕ» — шрифтом `Slovic`, основа — чёрное на белом, бегущая строка из повторённого имени, цвет — в изделиях (гжельский синий принт), текст — Montserrat. Лицензии этих двух шрифтов неизвестны — берём открытые аналоги (вопрос 5).

## 3. Предложение (агент, `/task-start`)

### 3.1. Понимание задачи

Создать frontend-каркас, на котором будут строиться все экраны MVP: инструменты (Vite, React, TypeScript strict, Tailwind, Router, TanStack Query, i18next, Vitest, Testing Library, MSW), оболочку приложения с нижней навигацией и заглушки четырёх разделов. Главное отличие от строки BACKLOG — оператор хочет, чтобы уже каркас нёс фирменный стиль: современный русский, премиальный, с росписью (гжель/хохлома) и старорусскими заголовками, но при этом приложением ежедневно пользуются пожилые люди и подростки — значит, орнамент и необычные шрифты не должны мешать читать списки и нажимать кнопки. Поэтому сначала утверждаем визуальный концепт, потом закладываем его в токены и оболочку. Реальные экраны с данными — в следующих задачах (T-014, T-035…T-038), компоненты и макеты ключевых экранов — T-008.

### 3.2. Подход

**Шаг 0. Визуальный концепт на согласование** (до кода приложения; вопрос 2).

Отдельная HTML-страница (artifact в claude.ai, без кода приложения; оператору нравится этот формат) с 2–3 вариантами одного и того же экрана «Запасы» и **вариантами нижней навигации** (вопрос 9) на реальных примерах из 07-ui-ux (Молоко 1,5 л ≈ до 14.11, Пельмени 900 г, Сахар ≈ 20 кг · Избыток…): телефон 390px и ПК 1440px, светлая и тёмная тема, нижняя панель, заголовок, пустое состояние и экран входа с крупной типографикой. Оператор выбирает вариант (можно «взять шрифт из А, палитру из Б»), решение записывается в `docs/10-design.md`. Инструментальную часть ведёт навык `taste-skill` (раздел «App screens»: `draw.mjs --app` для раздачи вариантов, `inspect.mjs --app` для замеров) — ему нужен Node 22+ (вопрос 1).

**Замысел (идея из самого продукта, не из категории; уточнён после ответа оператора):**

> «Закрома» — это **дом, в котором всё на своих местах**: тёплый, спокойный, обжитой интерфейс, где **места хранения — холодильник, морозилка, шкаф, балкон — узнаются с первого взгляда**, а роспись — как вышитый край полотенца: заметна, но не спорит с содержимым.

**Приоритеты (оператор): функциональность > дизайн; главное — домашний уют, гармония, современность и ощущение дорогой вещи; орнамент и необычный шрифт — дополнение, а не центр внимания.**

- **Уют — главное:** тёплая основа (тёплый фарфоровый белый в светлой теме, глубокий лаковый — в тёмной), мягкие крупные формы мест хранения, спокойный ритм, щедрые отступы, тёплые нейтральные тона. «Дорого» — за счёт типографики, точной сетки и глубоких цветов, а не за счёт золота, теней и градиентов.
- **Где появляются старорусский шрифт и роспись (точечно, «спокойно, но с выделением основных моментов» — ответ на вопрос 3):** слово-логотип «Закрома», заголовок раздела, небольшая эмблема у места хранения, тонкая кайма под шапкой, крупная типографика на экранах входа и в пустых состояниях («В морозилке пусто»).
- **Где её нет (рабочий слой):** строки продуктов, количества, сроки, кнопки, уровни запаса — ясный гротеск, табличные цифры, цвет только на смысле (уровни, сроки). Это требование 07-ui-ux (бабушка и подростки) и правило навыка для экранов приложения: «цвет — на данных, а не на оформлении».
- **Темы как две росписи:** светлая — **гжель** (белый фарфор, кобальт), тёмная — **хохлома** (чёрный лак, киноварь, золото-охра). Так требование NFR-UX-05 «светлая и тёмная тема» само становится частью замысла (вопрос 4).
- **Шрифты:** заголовки — открытый шрифт в духе устава/полуустава (кандидаты: **Triodion**, **Ponomar** — Александр Андреев, OFL; **Ruslan Display** — OFL); основной текст — **Golos Text** (Королькова/Кузьмин, OFL; делался для максимальной читаемости госсервисов). Выбор — по концепту, после проверки, что в шрифте заголовков есть все современные буквы (ё, й, ы, э) и он читается в 28–32px (вопрос 5).
- **Орнамент:** собственная векторная роспись (SVG), нарисованная по мотивам (цветок-«купавка», травный завиток, ягода, кайма-«бегунок»), а не копия конкретных изделий; слова «Гжель»/«Хохлома» не используем в названии и логотипе (Гжель — охраняемое наименование места происхождения товара). Дополнительно, по желанию, — фотографии музейных предметов из открытых коллекций (Wikimedia Commons и др.) с подписью автора и лицензии, только на экранах входа и «О приложении» (вопрос 6).
- **Цвета уровней** (07-ui-ux §3.4: серый, красный, оранжевый, зелёный, синий, фиолетовый) сохраняю по смыслу и порядку, подбираю оттенки под палитру и контраст AA (вопрос 8).

**Шаг 1. Каркас** (после утверждения концепта):

1. `frontend/` — Vite + React + TypeScript (`strict`, `noUncheckedIndexedAccess`), pnpm, `.nvmrc` / `engines` (вопрос 1).
2. Структура из architecture §3: `src/app` (провайдеры, роутер, оболочка), `src/features/{inventory,expiry,shopping,add,family}` (заглушки разделов по вопросу 9), `src/shared/{ui,format,theme}`, `src/i18n/ru`, `src/api` (пусто до T-005), `src/test` (MSW, утилиты).
3. Стиль: токены в `src/shared/theme/tokens.ts` (единственный источник) → CSS-переменные для светлой/тёмной темы → Tailwind v4 `@theme`; SVG-орнаменты как React-компоненты; шрифты — самостоятельно размещённые woff2 (Cyrillic-подмножество).
4. Оболочка: `AppLayout` — шапка (логотип, «Мой дом ▾»-заглушка), кайма, контент, нижняя панель (телефон) / боковая (≥ 1024px), центральная «＋ Добавить» 56–64px; панель строится из одного массива пунктов `NAV_ITEMS` (навигация предварительная); маршруты `/`, `/expiry`, `/add`, `/shopping`, `/family`; заглушки экранов с пустыми состояниями в стиле концепта.
5. TanStack Query (`QueryClientProvider`, без запросов к API — их добавит T-005), i18next (`ru`, plural-ключи), MSW только в тестах (dev-моки — позже, когда появится API).
6. Качество: ESLint (typescript-eslint, react-hooks, jsx-a11y), Prettier, Vitest (jsdom) + Testing Library + user-event + jest-dom; скрипты `dev/build/preview/test/lint/typecheck/format`; проверка размера бандла после сборки.
7. pre-commit: хуки eslint/prettier из T-001 «оживают» (AC-1); при необходимости поправлю их `entry` (в T-001 они не запускались — L-017).
8. Документация: `docs/10-design.md` (арт-дирекция и токены), `CLAUDE.md`/`README.md` (Node, pnpm, команды), architecture §3/§5 — если структура уточнится.

Уроки: **L-001/L-002** (сначала согласование, вопросы пачкой), **L-003** (зависимости — вопрос 7), **L-010** (никаких действий только жестами), **L-011** (бытовые слова), **L-014/L-016** (на Windows — явные пути к инструментам), **L-017** (проверить шрифт заголовков на всех буквах и на читаемость, проверить хуки eslint/prettier на реальном файле).

### 3.6. Риски, альтернативы, вне рамок

- **Читаемость против «росписи».** Уставные шрифты трудно читать в мелком размере и длинном тексте — поэтому только заголовки ≥ 24px и короткие слова; списки — Golos Text. Проверяется на концепте до кода.
- **Конфликт с правилами навыка для экранов приложения** (строгий гротеск, без декоративных форм, заголовки ≤ 32px внутри рабочих экранов). Решение: фирменный слой — осознанное исключение «бренда» (навык это допускает: `--allow` с причиной), но только в слое идентичности; рабочий слой следует правилам навыка.
- **«Дорого» ≠ «много»:** премиальность — от крупной типографики, точной сетки, глубоких цветов и сдержанного орнамента, а не от золота повсюду, градиентов и теней (их в рабочем слое нет).
- **Лицензии:** только OFL-шрифты и собственный орнамент; фотографии из открытых коллекций — с указанием автора и лицензии. Шрифты vechestore.ru не используем.
- **Вес шрифтов:** уставной шрифт подключается только для заголовков, подмножество кириллицы, `woff2`; основной — 2–3 начертания.
- **Node на машине нет** — без него не запускаются ни каркас, ни инструменты навыка (вопрос 1).
- **Вне рамок:** реальные экраны с данными и действия (T-014, T-035…T-038), API-клиент (T-005), PWA, service worker и иконки (T-040), CI (T-006), e2e (T-043), библиотека компонентов и детальные макеты ключевых экранов (T-008), Radix-компоненты (появятся с первыми интерактивными компонентами).

### Второй круг вопросов (после ответов оператора 2026-10-23)

**Почему в первой редакции не было варианта «Node в Docker».** Я по инерции повторил схему T-001/T-002 (uv на хосте) и не проверил альтернативу — ошибка в духе только что записанного урока L-017. Ниже — эксперимент на этой машине (scratch-каталог, вне проекта; Vite + React + TS, Node 24.22.1, pnpm 10.34.8):

| Замер | `node_modules` на диске Windows (bind mount) | `node_modules` в томе Docker |
|---|---|---|
| `pnpm install` | 10 с | 2 с |
| `vite build` / `tsc -b` | 2 с | 1 с / 1 с |
| Пакеты видны Windows-редактору (VS Code) | да, но symlink'и pnpm, созданные в контейнере, Windows не может даже удалить | нет — у редактора нет типов и ESLint |
| Правка файла из Windows → событие в контейнере | 0 событий inotify; изменение видно только опросом (polling) | то же |

Что из этого следует:

- **Docker годится** при условиях: `node_modules` и хранилище pnpm — в томах Docker (не на диске Windows), Vite следит за файлами опросом (`server.watch.usePolling`, небольшая нагрузка на CPU), порт dev-сервера — только `127.0.0.1` (как у БД).
- **Плюсы Docker:** ничего не ставится в Windows; та же версия Node, что будет в сборке образа (T-007) и в CI (T-006); скрипты установки npm-пакетов выполняются в контейнере, а не с правами пользователя Windows (защита от вредоносных пакетов).
- **Минусы Docker:** редактору (VS Code 1.143 у вас установлен) нужны пакеты — решается расширением **Dev Containers** (редактор работает «внутри» контейнера, типы и ESLint есть); каждая команда — через `docker compose run --rm web pnpm …` (≈1–2 с накладных); хуки pre-commit для eslint/prettier тоже идут через Docker (коммит медленнее на секунды; Docker Desktop должен быть запущен); инструментам навыка дизайна (`inspect.mjs`) нужен Chrome рядом с Node — в контейнере это отдельный образ с Chromium (например, официальный образ Playwright, ~1,5 ГБ), он же пригодится для e2e в T-043.

| Сложность | Как обнаружено | Решение |

| Node.js не было на машине | проверка окружения в `/task-start` | оператор установил Node 24.22 + pnpm 12.15; в терминале агента — явный PATH (L-016) |
| Правила навыка для рабочих экранов (один гротеск, заголовки ≤ 32px, без декора) против фирменной росписи | чтение `references/app-screens.md` | роспись и уставной шрифт — слой идентичности (осознанное исключение «бренда»), рабочий слой — по правилам навыка |
| Шрифты референса (vechestore) без открытой лицензии | разбор страницы в браузере | открытые аналоги из Google Fonts; покрытие кириллицы проверено fontTools (у Triodion нет только «№») |
| Свежие мажоры несовместимы: typescript-eslint требует TS < 6.1, jsx-a11y — ESLint ≤ 9 | `npm view … peerDependencies` до установки | TypeScript 6.0.3, ESLint 9.39 (L-025) |
| В SVG-атрибутах `fill="var(--…)"` не работает; узор каймы вне макета не получал цвет | снимки headless Chrome | цвета через `style`/классы Tailwind; кайма — CSS-маска |
| Headless Chrome не делает окно уже ~500px | обрезанный снимок «390» | замеры — инспектором навыка (эмуляция устройства) и встроенным браузером |
| `restoreMocks` сбрасывал заглушку `matchMedia` из setup | 20 тестов с `matchMedia is not a function` | заглушка — обычная функция в `beforeEach` (правило в rules/tests.md) |
| MSW 3 переименовал `onUnhandledRequest` → `onUnhandledFrame`; тесты были зелёными | ошибка `tsc` | новое имя; проверено, что незамоканный запрос роняет тест (L-026) |

| Bash-инструмент не разбирает длинные heredoc с обратными кавычками | ошибка `unexpected EOF` дважды | такие файлы — инструментом Write (L-027) |
