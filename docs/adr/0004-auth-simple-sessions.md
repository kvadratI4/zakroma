# 0004. Авторизация: email + пароль, серверные сессии, ссылки для приглашения и сброса

- Статус: Accepted
- Дата: 2026-10-23

## Контекст

Требование оператора: «проще — лучше». Пользователи — семья, включая пожилых. Почтовый сервер из РФ — лишняя сложность (доставляемость, настройка). Все члены дома равны.

## Решение

1. **Логин — email, пароль ≥ 8 символов.** Email не подтверждается (не нужен почтовый сервер).
2. **Долгая серверная сессия:** случайный токен в cookie `HttpOnly; Secure; SameSite=Lax`, в БД — его SHA-256. Срок 180 дней, продлевается при использовании. Пользователь входит практически один раз на устройство.
3. **Приглашение — ссылка** (`/invite/<token>`, 7 дней, многоразовая, отзываемая). Делится через Web Share (мессенджер).
4. **Сброс пароля — ссылка, которую создаёт другой член дома** (24 часа, одноразовая). После сброса все сессии пользователя завершаются.
5. Пароли — Argon2id. Ограничение попыток входа.

## Альтернативы

- Magic link по почте — требует SMTP и доставки писем; отложено.
- Вход через Яндекс ID / Telegram — удобно, но требует регистрации приложений у провайдеров и домена; этап «позже», схема (`user_identities`) добавляется тогда же.
- JWT без серверного хранения — сложнее отзывать; для одного сервера преимуществ нет.

## Последствия

- Пользователь, который единственный в доме и забыл пароль, восстанавливается только оператором вручную (скрипт `backend/scripts/reset_password.py`). Приемлемо для семейного приложения.
- Email не проверен: опечатка в email не мешает работе (это только логин).
