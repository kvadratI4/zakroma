# 0011. Изоляция интеграционных тестов БД: транзакция с откатом на тест

- Статус: Accepted
- Дата: 2026-10-23
- Задача: T-003

## Контекст

Интеграционные тесты идут на реальном Postgres (testcontainers, [08-testing](../08-testing.md)). Тесты не должны видеть данные друг друга, а прогон должен оставаться быстрым: тестов будут сотни (права доступа для каждого маршрута дома, события журнала, конфликты версий). Код приложения сам вызывает `commit()` — сервис открывает транзакцию на запрос. Журнал `stock_events` запрещает `UPDATE`/`DELETE` триггерами (L-006), поэтому очистка через `DELETE` невозможна.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Транзакция на тест с откатом, `commit()` приложения → `SAVEPOINT` | миллисекунды на тест; миграции один раз на прогон; не нужен список таблиц; триггеры не мешают | не подходит коду, который открывает **второе** соединение (фоновые задачи) |
| `TRUNCATE … CASCADE` всех таблиц после теста | честно для любого числа соединений | медленнее; нужно поддерживать список таблиц; порядок и последовательности |
| Новая БД из шаблона на каждый тест | полная изоляция | секунды на тест |

## Решение

1. Один контейнер `postgres:18` на прогон pytest (фикстура `postgres`, session). Порт — только `127.0.0.1`, пароль случайный на прогон; Ryuk (уборщик testcontainers) отключён, контейнер останавливает фикстура.
2. Общая тестовая БД один раз мигрируется до `head` (фикстура `database_url`).
3. На каждый тест: отдельное соединение → внешняя транзакция → `AsyncSession(bind=connection, join_transaction_mode="create_savepoint")` (фикстура `db_session`). `commit()` в коде приложения фиксирует только savepoint; после теста внешняя транзакция откатывается.
4. Приложение в тестах получает эту сессию через `app.dependency_overrides[get_session]` (фикстура `app`).
5. Тесты миграций создают **отдельную пустую БД** рядом с общей и удаляют её после теста.
6. Исключение: тест кода с собственными соединениями (фоновые задачи S2+) использует `TRUNCATE … CASCADE` после себя — решение принимается в его задаче.

Проверка, что изоляция работает: `tests/integration/test_db_session.py::test_commit_inside_test_is_rolled_back_afterwards` (данные после `commit()` не видны другому соединению); тест проверен на заведомо сломанной фикстуре — падает.

## Последствия

- Плюсы: быстрые независимые тесты; фабрики (T-010, T-011) пишут прямо в `db_session`.
- Минусы / долг: код, который сам создаёт `AsyncSession` из глобального sessionmaker в обход `get_session`, изоляцию обходит — так писать нельзя (правило в `.claude/rules/tests.md`).
