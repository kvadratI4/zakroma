# 0006. Количество: базовые единицы, режим «уровень», четыре порога

- Статус: Accepted, частично заменён [ADR-0013](0013-presence-tracking-household-measures.md) (2026-10-26): `portion` → бытовые меры и порог `critical_below`; `keep_in_stock` → «норма дома»
- Дата: 2026-10-23

## Контекст

Оператор: «можно грубо оценивать (много, мало), но дополнительно указывать сколько». Нужны понятия «очень много — не покупать» (20 кг сахара) и «смешно мало» (50 г макарон).

## Решение

- Количество хранится в базовой единице продукта (`g`, `ml`, `pcs`), `numeric(12,3)`.
- Шкала уровней из 6 значений: `out, critical, low, normal, plenty, excess`.
- Партия хранит `quantity` (может быть `null`), `quantity_is_approx`, `level` (ручной, может быть `null`).
- У продукта 4 порога: `portion`, `low_below`, `plenty_from`, `excess_from`. Уровень по количеству вычисляется, ручной уровень главнее.
- Флаг продукта `keep_in_stock` — предупреждать, когда продукт закончился.

Подробные правила и тест-векторы — [05-domain-rules.md](../05-domain-rules.md).

## Последствия

- Пользователь может вести учёт так грубо, как хочет, без потери возможности уточнить.
- Пороги — на продукт дома; стартовые значения приходят из справочника и могут быть неточными → оператор правит справочник/продукты.
- Перевод «штуки ↔ граммы» отложен до рецептов (S3).
