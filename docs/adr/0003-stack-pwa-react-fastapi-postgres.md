# 0003. Стек: PWA (React + TypeScript) + FastAPI + PostgreSQL

- Статус: Accepted
- Дата: 2026-10-23

## Контекст

Нужны телефон (Android и iOS) и ПК, один разработчик с ИИ-агентом, будущие этапы с LLM, разбором чеков и YouTube. Данные связные (дом → места → продукты → партии → события → рецепты).

## Решение

- Клиент: **PWA** на React + TypeScript (strict) + Vite + Tailwind + TanStack Query.
- Сервер: **Python + FastAPI**, SQLAlchemy 2 (async), Alembic, Pydantic v2, uv.
- БД: **PostgreSQL** (+ расширение `pg_trgm` для поиска).

## Альтернативы

- Нативные приложения / Flutter / React Native — дороже в 2–3 раза, магазины приложений не нужны.
- TypeScript на backend (NestJS/Fastify) — единый язык, но экосистема для LLM/OCR/разбора данных слабее; типобезопасность между частями достигается генерацией клиента из OpenAPI (ADR-0008).
- NoSQL (Firestore, MongoDB) — неудобны запросы вида «что скоро испортится по всем местам», «какие рецепты можно приготовить».
- SQLite — нет конкурентной записи на уровне, нужном семье, нет триграммного поиска.

## Последствия

- Два языка в репозитории; дисциплина: доменная логика только на backend, frontend её не дублирует (кроме форматирования).
- iOS: PWA без пуш-уведомлений, пока приложение не установлено на экран «Домой» — для MVP не важно.
