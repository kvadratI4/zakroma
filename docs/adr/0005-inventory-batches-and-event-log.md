# 0005. Запасы: партии + неизменяемый журнал событий

- Статус: Accepted
- Дата: 2026-10-23

## Контекст

Один продукт может лежать в нескольких местах и быть куплен в разные дни с разными сроками (молоко в понедельник и в пятницу). Будущие функции («хватит на…», статистика выброшенного, интервал покупок) требуют истории.

## Решение

- **Партия** (`inventory_items`) — одна покупка одного продукта в одном месте: количество/уровень, даты, срок. Текущее состояние хранится в партии (не вычисляется из журнала).
- **Журнал** (`stock_events`) — каждое изменение партии пишется событием в той же транзакции. Журнал только дополняется.
- Закончившиеся партии закрываются (`finished_at`), а не удаляются.

## Альтернативы

- Одна строка на продукт с суммарным количеством — теряются сроки разных покупок.
- Event sourcing (состояние только из событий) — избыточно сложно для семейного приложения.

## Последствия

- Каждая мутация в сервисном слое обязана писать событие — проверяется интеграционными тестами.
- Таблица событий растёт (оценка: < 50 000 строк в год на семью — не проблема).
