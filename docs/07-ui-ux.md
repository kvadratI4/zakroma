# 07. UI/UX

Цель — чтобы приложением пользовались **и подростки, и бабушка**, каждый день, без усилия. Каждый экран проверяется против [NFR-UX](02-requirements.md#удобство-ux) и вопросов-проверок [01-vision](01-vision.md#вопросы-проверки):

1. Удобно ли это не только молодым, но и старшим?
2. Будет ли человек делать это в обычной жизни?
3. Упростит ли это ему жизнь?

Модель за экранами — **учёт наличия** ([ADR-0013](adr/0013-presence-tracking-household-measures.md)): экран отвечает «что есть, чего нет, что купить», а не «кто сколько съел».

> Схемы ниже — смысл и порядок элементов. Как это выглядит, решают макеты [T-008a](../tasks/T-008a.md) (страница-концепт, `docs/design/screens.html`) и стиль [10-design](10-design.md). Круг 1 макетов (2026-10-26) принят частично: строка продукта — в две строки, «Сколько?» — отдельным экраном, выбор темы — в настройках; второй круг строится по этому документу.

## 1. Принципы

1. **Наличие, а не потребление.** Главные действия — «Закончилось», отметка уровня, «Выбросить», «Купили». Отмечать, сколько съели, можно, но никогда не нужно.
2. **Бытовые меры.** Количество — словами кухни: «2 пакета», «≈ 5 пакетиков», кнопки «−1 стакан», «−½ пачки». Граммы и миллилитры — там, где мер нет (мясо на вес) или человек выбрал точное количество.
3. **Значения по умолчанию заполнены и видны.** Место, количество, срок, дата покупки — «как в прошлый раз» и из справочника ([05 §8](05-domain-rules.md#8-значения-по-умолчанию-при-добавлении-как-в-прошлый-раз)). Каждое поле видно на экране и правится там же. Срок по умолчанию — типовой («≈ до 17.11, обычно неделя»), а не «не указан».
4. **Видимые действия вместо жестов.** Свайпы и долгие нажатия — только как дублирование видимых кнопок (взрослые их не находят, L-010).
5. **Одна главная кнопка на экране** — крупная, внизу, в зоне большого пальца.
6. **Слова, а не термины**: «Закончилось», «Выбросить», «Почти нет», «Мало» — без «списание», «партия», «инвентаризация» в UI (это слова для кода и документации, L-011). Кнопки списания называются одинаково: минус, число и мера — «−1 стакан», «−½ пачки»; отметки — словом с заглавной буквы: «Закончилось», «Выбросить».
7. **Отмена вместо подтверждений.** После действия — тост «Молоко: закончилось · Отменить» (5 с). Модальные «Вы уверены?» — только для необратимого (покинуть дом).
8. **Цвет не единственный носитель смысла**: у уровней и статусов есть текст/иконка.
9. **Мобильная раскладка первична**; на ПК — две колонки (список + карточка или добавление).

## 2. Навигация

> **Предварительная** (T-004, решение оператора 2026-10-23/24; «Семья» → «Настройки» — 2026-10-26, T-008r): пять мест, «Добавить» ровно по центру. Пересматривается после пилота (T-044) или по решению оператора; в коде — один список пунктов `NAV_ITEMS`. Стиль — [10-design.md](10-design.md).

Нижняя панель (на ПК — боковая, «Добавить» — кнопкой над пунктами):

| Вкладка | Вопрос семьи | Экран |
|---|---|---|
| Запасы | Что есть дома? | Продукты по местам или по видам; проверка места |
| Сроки | Что съесть первым? | Просрочено, скоро испортится (число на значке) |
| **＋ Добавить** | Что мы купили? | Добавление списком (центральная крупная кнопка) |
| Покупки | Что купить? | Закончилось, почти нет, мало; «Пока не покупать» (число на значке); в S3 — список покупок |
| Настройки | — | Кто живёт в доме и приглашение, места хранения, настройки дома, мои настройки (оформление), переключение дома |

Заголовок экрана: название дома (нажатие → переключение дома, если их несколько).

## 3. Экраны MVP

### 3.1. Вход / регистрация / приглашение

- Регистрация: email, пароль (с кнопкой «Показать»), «Как вас зовут». Без подтверждения почты.
- Ссылка-приглашение открывает экран «Вас пригласили в дом „Квартира"» → «Создать аккаунт» / «У меня уже есть аккаунт». Приглашают тех, кто живёт в этой квартире: у родственников в другой квартире — свой дом.
- После первого входа — экран «Установите приложение» с инструкцией под платформу (Android: кнопка установки; iOS: «Поделиться → На экран Домой» с картинкой; ПК: иконка в адресной строке). Можно пропустить.
- Круг 1 макетов: экраны входа и регистрации по приглашению приняты (изба на входе — единственная крупная картинка).

### 3.2. Запасы

```
┌───────────────────────────────────┐
│ Закрома        Квартира ▾     🔍  │
│ Добрый вечер                      │
│ Сметану пора выбросить ·          │
│ ещё 2 в «Сроках» ›                │
│ [По местам] [По видам]   [Фильтр] │
├───────────────────────────────────┤
│ ✿ ХОЛОДИЛЬНИК  · проверено вчера  │
│ Молоко 3,2 %          1 пакет   › │
│ ≈ до 17.11              [Мало ▾]  │
│ Творог 5 %         ½ пачки     ›  │
│ Сегодня последний день  [Мало ▾]  │
│ Морковь                       ›   │
│ ≈ до 09.11          [Нормально ▾] │
│ [ Проверить холодильник ]         │
└───────────────────────────────────┘
```

- **Приветствие** называет одно самое важное (FR-VIEW-06): просрочено → сегодня последний день → закончилось нужное → «Всё основное есть». Если важного больше — «ещё N» со ссылкой на «Сроки» или «Покупки».
- **По местам** — места хранения панелями с эмблемами; продукт, лежащий в нескольких местах, показан в каждом своей частью. **По видам** — категории (молочное, хлеб, крупы, мясо…) со сводкой продукта по всем местам: ответ на «есть ли из чего сделать бутерброд».
- **Строка продукта** — две строки (выбор оператора, круг 1): название и количество в мерах; ниже — срок или статус словом. Нажатие на строку (со стрелкой «›») открывает карточку.
- **Уровень в строке — это кнопка.** Нажатие открывает ряд из шести уровней и быстрых действий этого продукта: «Закончилось», меры («−1 стакан», «−½ пачки»), «Выбросить». Отметка — вторым нажатием, без перехода (NFR-UX-02). Точный вид — второй круг макетов T-008a.
- У места — «проверено вчера» и кнопка «Проверить холодильник» (§3.7).

### 3.3. Добавление (＋)

Один экран-список (FR-INV-04): и для одного продукта, и для всех покупок после магазина. Позиции чека (S2) попадают в этот же список.

```
┌──────────────────────────────────┐
│ ‹ Отмена      Что купили?        │
│ 🔍 мол|                          │
│ Молоко 3,2 %   дома: 1 пакет     │
│ Молоко топлёное 4 %              │
│ ──────── Добавляем: 2 ────────── │
│ Молоко 3,2 %                     │
│   [−] 2 пакета по 930 мл [+]     │
│   Куда: [✿ Холодильник ▾]        │
│   Годен до: ≈ 17.11 (обычно      │
│   неделя) [+3][+7][+14][Дата]    │
│ Хлеб бородинский · 1 буханка ·   │
│   Кухонный шкаф · ≈ до 31.10   › │
│                                  │
│      [ Добавить 2 продукта ]     │
└──────────────────────────────────┘
```

- **Поиск** сверху; пока поле пустое — «Обычно покупаете» (по частоте покупок). Выбранный продукт сразу попадает в список «Добавляем» со значениями «как в прошлый раз»: место, количество в мере покупки, типовой срок «≈».
- **Последний добавленный продукт раскрыт:** количество (−/+ в мерах, «или точно» — граммы/литры), место, срок (быстрые +3, +7, +14, +30 дней и календарь) видны и правятся на месте. Остальные — одной строкой; нажатие раскрывает.
- **Путь в 2–3 нажатия:** «Добавить» → строка «Молоко» в «Обычно покупаете» → «Добавить 1 продукт». С поиском — 3.
- **Продукты на вес и по уровню** (картофель с рынка): количество в мерах («3 кг», «1 сетка») или без количества — тогда «Нормально». Уровень после добавления считает приложение; спрашивать «сколько стало» не нужно.
- **Черновик списка** хранится на устройстве: закрыли приложение или пропала сеть — список на месте до «Добавить».
- **Несколько одинаковых** («2 пакета») — счётчиком, а не повторным выбором.
- Выбор оператора (круг 1): шаг «Сколько?» — **отдельный экран**, а не панель снизу. В этой схеме он становится раскрытой строкой списка на том же экране; если во втором круге раскрытая строка окажется тесной, редактирование открывается отдельным экраном «Сколько?» с кнопкой «Назад».

### 3.4. Выбор уровня

Ряд из 6 кнопок с цветом **и** подписью (решение оператора: шесть уровней):

`[Нет] [Почти нет] [Мало] [Нормально] [Много] [Избыток]`

Цвета: нет — серый, почти нет — красный, мало — оранжевый, нормально — зелёный, много — синий, избыток — фиолетовый. Порядок и цвета одинаковы везде. При «Почти нет» и «Мало» рядом — подсказка в мерах: «≈ 5 пакетиков», «меньше стакана» ([05 §1.2](05-domain-rules.md#12-подсказка-в-мерах)).

### 3.5. Карточка продукта

- **Наличие:** сколько всего в мерах («1,5 пакета», «≈ 5 пакетиков»), уровень словом, ближайший срок, где лежит.
- **Где лежит** — по местам, у каждой части: сколько, срок, «вскрыто», кнопки быстрых действий (меры, «Закончилось») и меню «⋯» (Вскрыто, Переместить, Выбросить, Исправить).
- **Норма дома:** «Всегда держать дома: [вкл] не меньше [1] [пакета]» с пояснением «Когда станет меньше — появится в „Покупках"».
- **Как покупаем и как берём** — бытовые меры продукта (меняются: «пакет 930 мл», «стакан 200 мл»).
- **История** — свёрнута («История · 12»): кто купил, кто выбросил, кто отметил «закончилось» («Мама · вчера · закончилось»).
- **Настройки продукта** (свёрнуты): название, вид, единица, сроки хранения, пороги «почти нет / мало / много / избыток» с пояснениями.
- S4: «хватит примерно на неделю», «обычно покупаете раз в 10 дней», «из 4 пачек 2 выброшены».

### 3.6. Сроки и Покупки (бывший экран «Внимание»)

Блоки и сортировка — по [правилам §6](05-domain-rules.md#6-сроки-и-покупки), данные — из `/attention`; экран разделён на два раздела меню (T-004). Круг 1 макетов: оба экрана приняты.

- **Сроки:** Просрочено → Скоро испортится. Кнопки — «Съели» / «Выбросить».
- **Покупки:** Закончилось → Почти нет → Мало, ниже — «Пока не покупать» (Избыток). Только продукты с нормой дома. При «Почти нет» и «Мало» — подсказка в мерах. Кнопка «Купили» открывает добавление с этим продуктом и значениями «как в прошлый раз» (в S3 — «В список покупок»).

### 3.7. Проверка места и ревизия

«Проверить холодильник» (FR-INV-12): список продуктов места с уровнем-кнопкой у каждого. Человек отмечает только то, что изменилось («Закончилось», «Мало», «Выбросить»), и нажимает главную кнопку «Остальное на месте».

**Предложение ревизии** (FR-INV-13, решение оператора 2026-10-26): раз в период — спокойная карточка в начале «Запасов»:

```
┌──────────────────────────────────┐
│ Сверим запасы?                   │
│ Последний раз — 3 недели назад.  │
│ Пройдём по местам, займёт        │
│ минут пять.                      │
│ [ Начать ]  [ Не сейчас ]        │
│ Как часто предлагать ›           │
└──────────────────────────────────┘
```

- «Начать» — места по очереди («Холодильник · 1 из 4»), в каждом — проверка места; можно остановиться в любой момент, проверенное сохраняется.
- В конце — итог: «С прошлой ревизии закончились: хлеб, молоко; стало мало: гречка» и кнопка «В покупки» (переход в «Покупки»).
- «Не сейчас» убирает карточку до следующего периода. Никаких значков на меню, красного цвета, окон поверх работы и упрёков.
- Период — в «Настройки → Мои настройки → Предлагать сверить запасы»: раз в неделю / раз в 2 недели / раз в 3 недели (по умолчанию) / раз в месяц / не предлагать.
- В MVP предложение видно только в приложении; уведомление на телефон или в Telegram — с T-400, с теми же настройками.

### 3.8. Настройки (бывшие «Дом» и «Семья»)

- **Кто живёт в доме:** участники, «Пригласить» (ссылка + «Поделиться» через Web Share API), «Сбросить пароль участнику».
- **Места хранения:** порядок (кнопками «выше/ниже», перетаскивание — дублирование), тип места, название.
- **Дом:** название, «Предупреждать о сроке — за 3 дня», часовой пояс.
- **Мои настройки:** имя, пароль, **оформление** («Как на устройстве / Светлое / Тёмное» — решение оператора, круг 1; T-009), **«Предлагать сверить запасы»** (раз в 1 / 2 / 3 / 4 недели или не предлагать; FR-INV-13).
- «Сменить дом», «Добавить дом», «Выйти».

## 4. Тексты

- Все строки — в `frontend/src/i18n/ru/*.json`, ключи по фичам (`stock.actions.markOut`, `stock.levels.critical`).
- Множественные формы — через i18next plurals (`1 день`, `2 дня`, `5 дней`); названия бытовых мер — из словаря мер с формами `one/few/many/gen` ([05 §1.1](05-domain-rules.md#11-бытовые-меры)).
- Тон — дружелюбный, без восклицательных знаков, канцелярита и упрёков («давно не проверяли», а не «вы не проверяли»).

## 5. Пилот

Перед закрытием MVP — две недели использования семьёй (T-044): записывать, где люди «застряли», в `docs/agent/LESSONS.md` (раздел UX) и превращать в задачи. Отдельно проверить: отмечают ли «Закончилось» и проверяют ли места — без этого учёт наличия «уплывает».
