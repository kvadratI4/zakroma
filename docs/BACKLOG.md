# BACKLOG (Kanban)

Единственный источник статусов задач. Агент меняет статус **только** своей текущей задачи и только по правилам [WORKFLOW](agent/WORKFLOW.md).

## Колонки

| Статус | Значение | Кто переводит |
| --- | --- | --- |
| `Backlog` | Идея, описана одной строкой | оператор |
| `Ready` | Есть критерии приёмки (ниже или в файле задачи), зависимости закрыты | оператор |
| `Proposal` | Агент написал предложение и вопросы, ждёт ответа | агент |
| `In progress` | Ответы получены, идёт TDD-реализация | агент |
| `Review` | DoD выполнен, ждёт приёмки | агент |
| `Done` | Принято оператором | оператор |
| `Blocked` | Нужна внешняя информация/решение (причина — в файле задачи) | любой |

**WIP-лимит: 1 задача** в `Proposal` + `In progress` одновременно.
Размер: **S** ≤ 1 сессии, **M** — 1–3 сессии, **L** — больше (такую задачу сначала разбить).

### Критерии приёмки MVP-задач (кратко; подробно — в файле задачи)

**T-002**

- pre-commit-хуки `ruff check` и `ruff format` срабатывают на изменённом файле в `backend/` (проверка: файл с нарушением → хук падает/исправляет).
- `.claude/settings.json` разрешает `Bash(pre-commit run *)` и `Bash(python docs/catalog/validate_catalog.py *)` (на Windows `python3` не работает — L-014).

**T-004**

- pre-commit-хуки `eslint` и `prettier` срабатывают на изменённом файле в `frontend/`.

**T-006**

- CI запускает `pre-commit run --all-files` — те же проверки, что локально.

**T-010**

- Регистрация с занятым email → `409 email_taken`; с паролем < 8 → `422 weak_password`.
- После входа cookie `HttpOnly; Secure; SameSite=Lax`, в БД хранится только хеш токена.
- 11-я неудачная попытка за 15 мин → `429 too_many_attempts`, даже с верным паролем.
- Изменяющий запрос с чужим `Origin` → `403`.
- Фикстура доступа: для каждого маршрута дома — `401` без сессии, `404` для чужого дома.

**T-011**

- Регистрация без приглашения создаёт «Мой дом» и места Холодильник (fridge), Морозилка (freezer), Кухонный шкаф (pantry).
- Член дома A получает `404` на любой путь дома B.
- Последний участник покидает дом → `archived_at` заполнен, данные не удалены.

**T-012**

- Ссылка работает 7 дней; отозванная/просроченная → `404 invite_invalid`.
- Повторное принятие членом дома — идемпотентно (`200`, без дубликатов).

**T-020**

- Миграция загружает 331 позицию; повторный запуск не создаёт дубликатов и обновляет изменённые поля.
- CI запускает `validate_catalog.py`.

**T-021**

- Повторное добавление того же `catalog_slug` возвращает существующий продукт.
- Продукт с порогами не по возрастанию → `422`.
- Архивирование продукта с активными партиями → `409 product_has_items`.

**T-022**

- Запросы «малако», «макорон», «памидор», «гричка», «смитана», «пенне», «мёд/мед» находят ожидаемый продукт в топ-3.
- Продукты дома выше позиций справочника при равной релевантности.
- p95 ≤ 50 мс на справочнике + 300 продуктах дома (локально).

**T-030**

- Все тест-векторы из [05-domain-rules.md](05-domain-rules.md) реализованы параметризованными тестами.
- Свойства hypothesis из [08-testing.md](08-testing.md#инварианты-для-property-based-тестов-hypothesis) проходят.
- Покрытие `app/domain` ≥ 90 % (строки и ветвления); модуль не импортирует FastAPI/SQLAlchemy (проверка тестом импорта).

**T-032**

- `packages: 2` при `package_size=450` → партия 900 г.
- Без `expires_on` в морозилку → срок по `shelf_life_frozen_days`, `source=estimated`.
- Пакет из 5 позиций, одна с ошибкой → `422`, ничего не сохранено.
- `PATCH` со старой версией → `409` с `current`.
- Каждое изменение → ровно одно событие корректного типа.

**T-033**

- Тест-векторы FEFO и clamp из доменных правил выполняются через API.
- Перемещение части партии создаёт новую партию с теми же датами; события `moved` у обеих.
- Уровень «Нет» закрывает партию.

**T-034**

- `/attention` возвращает блоки в порядке и с сортировкой из §6 доменных правил.
- `/stock?group=category` даёт сводку по продукту через все места.

**T-036**

- Добавление «Молоко» из плитки — 2 тапа (компонентный тест считает взаимодействия).
- Корзина «После магазина» переживает перезагрузку страницы.

**T-040**

- Lighthouse PWA: устанавливаемо; оболочка открывается офлайн; при офлайне кнопки изменений неактивны с подсказкой.
