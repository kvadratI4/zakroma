# BACKLOG (Kanban)

Единственный источник статусов задач. Агент меняет статус **только** своей текущей задачи и только по правилам [WORKFLOW](agent/WORKFLOW.md).

## Колонки

| Статус | Значение | Кто переводит |
| --- | --- | --- |
| `Backlog` | Идея, описана одной строкой | оператор |
| `Ready` | Есть критерии приёмки (ниже или в файле задачи), зависимости закрыты | оператор |
| `Proposal` | Агент написал предложение и вопросы, ждёт ответа | агент |
| `In progress` | Ответы получены, идёт TDD-реализация | агент |
| `Review` | DoD выполнен, ждёт приёмки | агент |
| `Done` | Принято оператором | оператор |
| `Blocked` | Нужна внешняя информация/решение (причина — в файле задачи) | любой |

**WIP-лимит: 1 задача** в `Proposal` + `In progress` одновременно.
Размер: **S** ≤ 1 сессии, **M** — 1–3 сессии, **L** — больше (такую задачу сначала разбить).

**T-008c** (черновик; уточняется по составу компонентов из T-008a)

- Строка продукта в две строки (выбор оператора, круг 1 T-008a): нажатие — карточка; уровень-кнопка открывает шесть уровней и быстрые действия продукта («Закончилось», бытовые меры, «Выбросить»); количество в мерах табличными цифрами, уровень, срок «до…» / «≈ до…», статусы «просрочено» / «скоро испортится» словом, а не только цветом; вся строка — одна цель нажатия с понятным именем.
- Панель места: эмблема (купавка — холодильник и прочие, снежинка — морозилка, колос — шкаф, рябина — балкон; цвета — токены росписи), название Triodion 24 px.
- Тост «Отменить»: 5 с, `aria-live="polite"`, пауза при фокусе и наведении, одна очередь, кнопка «Отменить» доступна с клавиатуры (07-ui-ux §1.5).
- Меню «⋯» и нижняя панель / диалог: фокус внутри, `Esc` закрывает, фокус возвращается; подтверждение — только для необратимого (покинуть дом).
- Состояния: скелеты загрузки, ошибка сети с повтором, офлайн — кнопки изменений неактивны с подсказкой (NFR-PLAT-03).
- Те же требования доступности, тестов, витрины и CSP, что у T-008b.

**T-009**

- Три варианта: «Как на устройстве» (по умолчанию, тема следует за системной, в том числе при смене во время работы), «Светлая», «Тёмная»; подписи — через i18n.
- Переключатель видимый (не жест, L-010), доступен с клавиатуры и экранному диктору (текущий вариант озвучивается), зона нажатия ≥ 44px; место — «Настройки → Мои настройки → Оформление» (выбор оператора, круг 1 T-008a, 2026-10-26).
- Выбор хранится на устройстве (`localStorage`), не в учётной записи: переживает перезагрузку; без доступа к `localStorage` (приватный режим) — «Как на устройстве», без ошибок.
- Тема до загрузки JS: токены `--zk-*` и сохранённый выбор применяются встроенным в `index.html` скриптом (генерируется при сборке из `tokens.ts`) — ни при тёмной системной, ни при выбранной вручную теме не мелькает белый экран (перенесено из T-040).
- Цвета — только из `tokens.ts`; контраст AA в обеих темах уже проверен (`tokens.test.ts`), новые токены — с тем же тестом.
- CSP prod-стека остаётся без `unsafe-inline`: встроенный скрипт темы разрешается в `script-src` по `sha256`-хешу, который вычисляется при сборке и попадает в Caddyfile; smoke-проверка CSP (`tests/smoke`) и проверка в браузере без нарушений (из T-007, ADR-0012).

**T-006**

- CI для frontend: `pnpm install --frozen-lockfile`, `typecheck`, `lint`, `format:check`, `test` с покрытием (порог 08-testing §6), `build`, `pnpm size` ≤ 300 КБ (из T-004).
- CI запускает `pre-commit run --all-files` — те же проверки, что локально.
- CI запускает `pre-commit run gitleaks-history --hook-stage manual --all-files` (на коммите хук видит только индекс) и интеграционные/миграционные тесты с Docker (из T-003, L-022).
- CI запускает `pnpm api:check` (схема backend = `openapi.json`, `schema.d.ts` = `openapi.json`); в одной задаче нужны uv и Node (из T-005).

**T-007**

- api запускается `uvicorn app.main:create_app --factory --proxy-headers --forwarded-allow-ips=<сеть compose>` (флаг `--no-access-log` не нужен — access-лог uvicorn отключён в коде).
- Caddy передаёт в api `X-Request-ID` (`request_header X-Request-ID {http.request.uuid}`): один id в логах Caddy и api.
- api подключается к БД отдельной ролью без прав суперпользователя; миграции выполняет роль-владелец схемы (из T-003).
- Образ Postgres закреплён по digest (не плавающий тег `postgres:18`) (из T-003).
- У сервиса `db` в prod-compose нет опубликованных портов — доступ только из сети compose; пароль БД — только в серверном `.env`, не в образах, compose-файлах и логах (из T-003, требование безопасности оператора).
- Caddy отдаёт заголовки безопасности: CSP без `unsafe-inline` для скриптов (встроенный скрипт темы из T-009 — по хешу), HSTS, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, `Permissions-Policy` без лишних разрешений; тест — запрос к prod-сборке (сводка 01, согласовано оператором 2026-10-24).
- В prod OpenAPI-схема не отдаётся: `/api/v1/openapi.json` и `/api/v1/docs` → `404`. Клиент генерируется из закоммиченного `openapi.json` при разработке, во время работы схема не нужна; `export_openapi` строит схему через `app.openapi()` и от маршрута не зависит. Проверка `schema.status_code == 200` в `test_docs_are_hidden_in_prod` меняется на `404` — согласовано оператором 2026-10-24 (сводка 01, §5.1 п. 4).

**T-041**
