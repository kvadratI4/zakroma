# Уроки проекта

Загружается в каждую сессию агента (через `CLAUDE.md`). Формат записи — [templates/LESSON.md](../../templates/LESSON.md). Добавлять — командой `/lesson` с подтверждением оператора. Держать коротким (≤ ~150 строк); устаревшее — в `LESSONS_ARCHIVE.md`.

Уроки `L-001…L-013` записаны заранее по итогам проектирования (2026-10-23); часть проверена на реальном Postgres при подготовке документации.

## Процесс

- **L-001** Не пиши код и тесты до ответа оператора на предложение. — Почему: оператор хочет согласовать подход до затрат. (проектирование)
- **L-002** Задавай вопросы пачкой, с вариантами и рекомендацией; не спрашивай то, что уже есть в docs. — Почему: экономит время оператора. (проектирование)
- **L-003** Не добавляй зависимости и внешние сервисы без явного «да». — Почему: проект живёт на маленьком VPS, каждая зависимость — поддержка. (проектирование)
- **L-017** В `/task-start` проверяй предположения о сторонних инструментах коротким экспериментом (какие порты открывает, что ловят правила по умолчанию, как ведёт себя с нашим стеком) и пиши результат в «Предложение». — Почему: в T-003 три предположения (порты testcontainers, правила gitleaks, coverage с async SQLAlchemy) оказались неверными и всплыли только при реализации. (T-003, 2026-10-23)
- **L-018** Любые учётные данные, даже для локальной разработки, — секрет: случайные, генерируются локально (`init_dev_env`), лежат в git-игнорируемом файле, не печатаются и не попадают в compose/код. — Почему: оператор отклонил «dev-пароль `zakroma` в compose — не секрет»; план пришлось пересогласовать. (T-003, 2026-10-23)
- **L-019** Если задача делает поле/зависимость обязательной, перечисли в плане правки **подготовки** существующих тестов (фикстуры, окружение), а не только изменения проверок. — Почему: в T-003 план называл один тест health, а правились фикстуры пяти модулей — пришлось объяснять это задним числом. (T-003, 2026-10-23)
- **L-023** Визуальные решения (стиль, навигация, раскладка) не записывай в критерии как согласованные, пока оператор не увидел их картинкой: сначала страница-концепт с 2–3 вариантами, потом код. — Почему: в T-004 оператор отклонил «согласованный» стиль и меню, не видя их; страница концепта сняла спор за один круг. (T-004)
- **L-035** Проверку, по которой решаешь «можно коммитить», запускай без `| tail`/`| grep` или с `set -o pipefail` и смотри её код выхода (`${PIPESTATUS[0]}`), а цепочку `a && b | tail && git commit` не строй. — Почему: в T-007 mypy нашёл 2 ошибки, но код выхода `tail` был 0, и коммит прошёл. (T-007, проверено)
- **L-024** В вариантах ответа на вопрос всегда указывай очевидные альтернативы, включая инструменты, уже используемые в проекте (Docker), и решай спор коротким замером с ценой каждого варианта. — Почему: в T-004 вариант «Node в Docker» не был предложен, оператор спросил «почему?». (T-004)
- **L-029** Убедись, что проверка действительно выполнилась: «Skipped (no files to check)», тест, зелёный с первого запуска, или RED по чужой причине (`ImportError`, `window is not defined`) — не результат. — Почему: в T-005 проверка истории gitleaks по команде из CLAUDE.md молча пропускалась, а два RED сначала падали не по той причине. (T-005, проверено)

## Данные и БД

- **L-004** Количества — только `Decimal` в базовой единице продукта (`g`/`ml`/`pcs`). — Почему: `float` даёт 0.30000000000000004 г и ломает сравнения с порогами. (проектирование)
- **L-005** Для нечёткого поиска используй `zk_search_fold()` + `word_similarity`/`<%`, а не `similarity`/`%`. — Почему: проверено — `%` не находит «макорон» в «макароны паста|…», а без свёртки гласных «малако» не находит «молоко». (проверено 2026-10-23)
- **L-006** Чисти тестовую БД через `TRUNCATE … CASCADE` или откат транзакции, не через `DELETE`. — Почему: триггеры `stock_events` запрещают DELETE (журнал только на запись). (проверено 2026-10-23)
- **L-007** При загрузке CSV справочника пустые `aliases` превращай в `''`, остальные пустые ячейки — в `NULL`. — Почему: `aliases NOT NULL`; `\copy` даёт NULL — загрузка падала. (проверено 2026-10-23)
- **L-008** Любой новый household-scoped объект — с `household_id` и составными FK `(household_id, x_id)`. — Почему: база сама не даст смешать данные домов. (проектирование)

## Backend

- **L-009** «Сегодня» — в часовом поясе дома и только через `Clock`/параметр, не `date.today()`. — Почему: сервер может быть в UTC, сроки «сегодня последний день» поедут на 3 часа. (проектирование)
- **L-033** В тестах `Settings` создавай только с `_env_file=None` (или под общей фикстурой, отключающей `deploy/.env.dev`), а перед первым CI прогоняй тесты на чистой копии (`git archive HEAD`) в Linux-контейнере. — Почему: в T-006 два unit-теста проходили у оператора только потому, что `Settings()` молча брал `DATABASE_URL` из `.env.dev` (тесты читали dev-пароль), на Linux они падали, а третий тест проходил по чужой причине. (T-006, проверено)
- **L-020** Для SQLAlchemy async в coverage нужен `concurrency = ["greenlet", "thread"]`; иначе строки после `await session.…` выглядят непокрытыми. Не меняй код ради покрытия, пока не исключена ошибка измерения. — Почему: сначала причиной ошибочно сочли `asyncio.timeout` и переносили код; помогла настройка coverage. (T-003, проверено 2026-10-23)
- **L-031** Описание API проверяй по сгенерированным типам и по реальным ответам, а не только по JSON схемы: поле pydantic с `default` `openapi-typescript` делает обязательным. — Почему: `Problem.detail` стал обязательным `string | null`, хотя сервер его опускает; поймал `tsc` на типизированном обработчике MSW. (T-005, проверено)

## Frontend / UX

- **L-010** Не прячь действия в жесты (свайп, долгое нажатие) без видимой кнопки. — Почему: пользуются пожилые члены семьи. (проектирование)
- **L-011** В интерфейсе — бытовые слова («Закончилось», «Выбросить»), не термины из кода («партия», «списание»). (проектирование)
- **L-028** Разделы и кнопки называй по вопросу семьи («Сроки» — что съесть первым, «Покупки» — что купить, «Семья»), а не по термину из документации («Внимание», «Дом»). — Почему: оператор не понял, что скрывается за «Внимание» и «Дом». (T-004)
- **L-030** HTTP-клиент, созданный при импорте модуля, должен брать `fetch` в момент запроса (`fetch: (r) => globalThis.fetch(r)`); проверяй, что тест с MSW действительно попал в обработчик. — Почему: `openapi-fetch` запомнил `fetch` до `server.listen()`, запрос ушёл в сеть мимо MSW, и `onUnhandledFrame` этого не увидел. (T-005, проверено)

## Документация

- **L-013** В Mermaid `sequenceDiagram` не ставь `;` в тексте сообщений (используй запятую). — Почему: `;` — разделитель операторов, диаграмма не рендерится. (проверено 2026-10-23)

## Окружение и интеграции

- **L-012** Не закладывай прямые вызовы OpenAI/Anthropic/Google API с сервера: VPS в РФ, доступ может быть заблокирован. Только через порт и ADR-0010. (проектирование)
- **L-014** На Windows оператора `python3` — заглушка Microsoft Store; в скриптах и хуках используй `python` (в pre-commit — `language: python`), в документации указывай оба варианта. — Почему: команда падала с «Python was not found». (T-001, 2026-10-23)
- **L-015** Перед `pre-commit run --all-files` добавь новые файлы в git (`git add`). — Почему: хуки проверяют только tracked/staged файлы, непроиндексированное молча пропускается. (T-001, 2026-10-23)
- **L-016** Если только что установленный инструмент (uv, pre-commit) даёт `command not found` в терминале Claude Desktop — вызывай его по явному пути (`~/.local/bin`, каталог uv из WinGet, `C:\Program Files\nodejs`, `%APPDATA%\npm`) или попроси перезапустить приложение, а не ставь заново; перед `git commit` экспортируй этот PATH — хуки ruff вызывают `uv` и иначе падают с `Executable uv not found`. — Почему: процесс приложения держит PATH на момент запуска. (T-001, T-002, T-004)
- **L-021** testcontainers: отключай Ryuk (`testcontainers_config.ryuk_disabled = True`), порт БД привязывай к `127.0.0.1`, а после запуска смотри порты **всех** контейнеров (`docker ps`). — Почему: Ryuk публикует порт на `0.0.0.0`/`::` и по сети принимает команды удаления контейнеров; план проверял только порт БД. (T-003, проверено 2026-10-23)
- **L-022** Сканер секретов проверяй на негативных образцах наших форматов (DSN, `*_PASSWORD=`, пароль в коде). Стандартные правила gitleaks **не** ловят пароль в DSN — свои правила в `.gitleaks.toml`; историю проверяет `pre-commit run gitleaks-history --hook-stage manual --all-files` (без `--all-files` при пустом индексе хук пропускается — T-005). — Почему: «хук стоит» ≠ «утечка ловится»; на коммите хук видит только индекс. (T-003, проверено 2026-10-23)
- **L-025** Перед установкой свежих мажорных версий проверяй `npm view <pkg> peerDependencies` у связанных пакетов. — Почему: в 2026-10 typescript-eslint требовал TypeScript < 6.1, а eslint-plugin-jsx-a11y — ESLint ≤ 9; установка «всего последнего» сломала бы линтер. Если peer не совпадает — проверь работу экспериментом и разреши версию явно (`peerDependencyRules` в `frontend/pnpm-workspace.yaml`), а не терпи предупреждение. (T-004, T-005, проверено)
- **L-026** После обновления библиотеки до нового мажора прогоняй `tsc` даже при зелёных тестах. — Почему: MSW 3 переименовал `onUnhandledRequest` → `onUnhandledFrame`; старая опция молча игнорировалась, тесты были зелёными, ошибку показал только typecheck. (T-004, проверено)
- **L-027** Файлы с обратными кавычками (JS/TS шаблонные строки, Markdown) пиши инструментом Write, а не длинным heredoc в Bash. — Почему: в T-003/T-004 Bash-инструмент падал с `unexpected EOF`, и ни один файл из пачки не записывался. (T-004, проверено)
- **L-036** Лимиты и защиты на прокси проверяй тестом против запущенного стека, а не по документации: в Caddy `request_body max_size` срабатывает, только когда upstream читает тело. Ранний отказ — по `Content-Length` (`header_regexp`). — Почему: в T-007 тест на 2 МБ получил 405 от api вместо 413 от Caddy. (T-007, проверено)
- **L-037** В терминале агента команды pnpm, которые могут задать вопрос (`pnpm add`, `pnpm install` после смены lock-файла), запускай с `CI=true` и ограничением по времени (`timeout`). — Почему: в T-007 `pnpm add` без TTY молча ждал ответа и завис на 5 минут. (T-007, проверено)
- **L-032** После остановки фоновых dev-серверов (`pnpm dev`, uvicorn) проверь порты (`netstat -ano`) и заверши оставшийся процесс по PID, убедившись по командной строке, что он твой. — Почему: на Windows остановка задачи завершила `pnpm`, а дочерний `vite` продолжал слушать 5173. (T-005, проверено)
- **L-034** Изменения CI проверяй до push: workflow — хуком actionlint, `dependabot.yml` — по схеме (`uvx check-jsonschema --builtin-schema vendor.dependabot`), оба — и на испорченном образце; задачи CI — теми же командами в Linux-контейнере на свежем клоне с полной историей. Интеграционные тесты testcontainers так не проверить: в Docker Desktop у контейнера свой `127.0.0.1`, даже с `--network host`, — их проверяет только первый прогон на раннере. — Почему: в T-006 первый прогон CI прошёл с первой попытки, а имитация заранее нашла тесты, зависевшие от машины разработчика (L-033). (T-006, проверено)
