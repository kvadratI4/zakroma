# Справочник продуктов

Стартовый глобальный справочник: **331 продукт в 26 категориях**. Загружается в БД data-миграцией (задача T-020); правила использования — [ADR-0007](../adr/0007-household-products-from-catalog.md).

> Значения — ориентиры для семьи из 3–4 человек, составлены «на глаз» по типичным упаковкам и срокам хранения. Их задача — дать разумные значения по умолчанию, а не точность. **Правьте смело**: любой продукт дома можно перенастроить в приложении, а этот файл — для всех будущих домов.

## Файлы

| Файл | Содержимое |
|---|---|
| `categories.csv` | `slug, name_ru, icon, sort_order` |
| `products.csv` | позиции справочника (колонки ниже) |

Редактировать удобно в Excel/LibreOffice/Google Sheets: **кодировка UTF-8, разделитель — запятая**. После правки — запустить валидатор.

## Колонки `products.csv`

| Колонка | Пример | Смысл |
|---|---|---|
| `slug` | `buckwheat` | Неизменяемый идентификатор (латиница, `_`). Не переименовывать после запуска — на него ссылаются продукты домов |
| `name_ru` | Гречка | Название в интерфейсе |
| `aliases` | `гречневая крупа` | Синонимы для поиска, через `\|` |
| `category` | `grains` | Slug из `categories.csv` |
| `unit` | `g` | Базовая единица: `g`, `ml`, `pcs` |
| `tracking_mode` | `exact` | `exact` — вводить количество; `level` — уровень (много/мало) |
| `default_location_kind` | `pantry` | Куда кладётся по умолчанию: `fridge`, `freezer`, `pantry`, `cellar`, `balcony`, `other` |
| `package_size` | `900` | Типичная упаковка в базовых единицах — для кнопки «+1 упаковка» (пусто — нет кнопки) |
| `portion` | `70` | Одна порция на человека. Меньше — «критически мало» |
| `low_below` | `300` | Меньше — «мало, пора докупить» |
| `plenty_from` | `3000` | От этого — «много» |
| `excess_from` | `8000` | От этого — «избыток, не покупать» |
| `shelf_life_days` | `540` | Типичный срок хранения в обычном месте (дней) |
| `shelf_life_opened_days` | | Срок после вскрытия |
| `shelf_life_frozen_days` | | Срок в морозилке |
| `keep_in_stock` | `true` | Предупреждать, когда закончилось («держать дома постоянно») |

Пустая ячейка = значение не задано. Пороги, если заданы, должны идти по возрастанию: `portion ≤ low_below ≤ plenty_from ≤ excess_from` — валидатор это проверит. Правила расчёта — [05-domain-rules.md](../05-domain-rules.md).

## Сознательные решения

- Овощи, фрукты, зелень, специи — режим `level` (без весов на кухне), пороги в граммах всё равно заданы — для случаев, когда пользователь укажет «≈ 2 кг».
- Консервы — в штуках (банках); `portion` не задан.
- Продукты без порогов (арбуз, торт, алкоголь) не дают предупреждений «мало/избыток» — это разовые покупки.
- Для замороженных продуктов `shelf_life_days` = срок **после разморозки** в холодильнике; основной срок — `shelf_life_frozen_days`.
- Категория «Готовая еда» — для домашних остатков (суп, котлеты): у них короткий срок, и именно они чаще всего портятся.
- Категория `other` пустая — для продуктов, созданных пользователями.

## Что стоит проверить оператору в первую очередь

1. `keep_in_stock = true` (сейчас у 20 позиций: картофель, лук, чеснок, морковь, молоко, масло сливочное, яйца, гречка, рис, макароны, мука, сода, хлеб, соль, перец чёрный, лавровый лист, масло подсолнечное, сахар, мёд, чай) — это то, о чём приложение напомнит, когда закончится.
2. Пороги для основных круп, сахара, муки — под реальные объёмы вашей семьи.
3. Недостающие продукты, которые вы покупаете регулярно.
